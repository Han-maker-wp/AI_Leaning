# 第 1 课：环境搭建与工具链

> 🎬 开场钩子：1989 年圣诞假期，荷兰程序员 Guido van Rossum 想给自己找点乐子：写一门介于 C 和 shell 之间的解释型语言当消遣。这个假期项目后来叫 Python——如今从本课程的脚本到 ChatGPT 的训练代码，跑的全是它。而你的第一步很朴素：把它装好。

## 本课目标

1. 终端能验证 Python 3.10+ 可用，知道 apt 与源码两种安装路径

## 1.1 先校准世界观：Python 和 Java 的执行模型差异

写第一行代码之前，必须先建立一个正确的心理模型，否则后面处处别扭。

Java 的世界：`.java` → `javac` 编译成 `.class` 字节码 → JVM 加载执行。编译期做完整的类型检查，类型错误在构建阶段就被拦下。

Python（CPython 实现）的世界：`.py` 文件直接交给解释器执行。CPython 内部其实也会把源码编译成字节码（缓存在 `__pycache__/` 里的 `.pyc`），但**没有独立的编译阶段、不做类型检查**——字节码生成后立刻逐条解释执行，类型检查发生在运行时。

> ☕ Java 视角：把 Python 想成「javac 那一步永远自动发生、且只查语法不查类型」的 Java。变量不声明类型、方法签名不写返回类型，类型错误要跑到那行代码才爆炸。补救手段是「类型提示」（第 4 课），IDE 与静态检查工具靠它工作，但运行时不强制。

另外两个立刻要适应的差异：

- **没有 main 类**：入口就是文件本身，从第一行开始执行
- **没有「先编译再跑」的等待**：改完即跑，开发循环比 Java 短得多

> 🍿 彩蛋｜Python 比 Java 还年长：Python 1.0 发布于 1991 年，Java 要到 1995 年才问世。你即将"新学"的这门语言其实是你主力语言的前辈——所以后面每课拿两者对比，是前辈与后辈的切磋。

## 1.2 检查与安装 Python 3.10+

```bash
python3 --version        # 输出 Python 3.10.x 及以上即可
```

**方式一：系统包管理器（Debian/Ubuntu）**

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip
```

注意：Ubuntu/Debian 系上 `venv` 是独立软件包，不装 `python3-venv` 的话 `python3 -m venv` 会报错。

**方式二：源码编译（了解即可，只在需要指定版本时用）**

```bash
./configure --prefix=$HOME/.local/python3.12
make -j$(nproc)
make altinstall        # altinstall 避免覆盖系统默认的 python3
```

铁律：**不要替换系统自带的 python3**，apt 等系统工具依赖它。要装新版本用 altinstall 装到用户目录，或者干脆用 uv 托管 Python 版本（`uv python install 3.12`）。

## 1.3 安装 uv：新一代 Python 工具链

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv --version            # 安装后重开终端或 source 配置文件再验证
```

uv 是用 Rust 写的 Python 全能工具：管 Python 版本、管虚拟环境、管依赖安装、管项目脚手架，安装依赖比传统 pip 快一个数量级。本课程后续默认使用 uv。

> ☕ Java 视角：uv 大致相当于 Maven/Gradle（依赖管理与项目构建）+ SDKMAN（多版本管理）的合体，但命令面小一个数量级，学习成本很低。

## 1.4 虚拟环境：为什么、以及两种创建姿势

**为什么需要虚拟环境**：Python 默认把包装进全局的 site-packages，多个项目共用一份依赖，版本一冲突就互相踩踏。虚拟环境 = 给每个项目一份独立的 Python + 独立的包目录。这相当于 Maven 里「每个项目自带独立依赖树」的概念，只是 Python 需要你显式创建。

**姿势 A：传统 venv（必须会，面试与老项目都还会遇到）**

```bash
python3 -m venv .venv          # 在当前目录创建 .venv/
source .venv/bin/activate      # 激活，提示符前出现 (.venv)
pip install requests           # 此时装的是「这个环境里」的包
pip list                       # 查看已装包
deactivate                     # 退出虚拟环境
```

激活的本质：把 `.venv/bin` 插到 PATH 最前面，之后的 `python3`/`pip` 都指向环境内的副本。

**姿势 B：uv（日常推荐）**

```bash
uv venv                        # 默认创建 .venv
uv pip install numpy           # 极速安装
uv pip list
uv run hello.py                # 自动在项目环境中运行脚本，可省激活
```

项目模式（`uv init` / `uv add` / `uv sync`，配合 pyproject.toml）在第 6 课细讲。

习惯：`.venv` 一律加进 `.gitignore`，环境不进版本库，靠配置文件复现。

## 1.5 第一个脚本与 REPL

创建 `hello.py`：

```python
# hello.py —— 第一个脚本
if __name__ == "__main__":     # 入口惯用法，第 6 课详解；现在照抄即可
    name = input("你的名字：")
    print(f"你好，{name}！欢迎来到 Python 世界。")
```

运行：

```bash
python3 hello.py
# 或
uv run hello.py
```

**REPL（交互式解释器）**：终端敲 `python3` 进入 `>>>` 提示符，敲一行执行一行：

```
>>> 1 + 1
2
>>> "py" * 3
'pypypy'
>>> exit()        # 或按 Ctrl-D 退出
```

> ☕ Java 视角：REPL 相当于 JDK 9+ 的 jshell，但它在 Python 圈是日常主力工具：想验证一行语法、看一个 API 返回什么，随开随用，零成本试错。

> 🍿 彩蛋｜Python 不是蟒蛇：名字来自 Guido 钟爱的英国喜剧团 Monty Python。官方教程用 spam、eggs 当示例变量名就是在致敬喜剧梗——以后在文档里看到 spam，别以为是垃圾邮件。

## 1.6 脚本的三种执行方式

```bash
# 1. 最常用
python3 hello.py

# 2. 可执行文件：首行加 shebang，再赋执行权限
#!/usr/bin/env python3        # hello.py 第一行
chmod +x hello.py
./hello.py

# 3. 模块方式运行（第 6 课讲 import 后会明白何时用它）
python3 -m 模块名
```

## 1.7 工具链：VS Code 与 Jupyter

**VS Code**：

1. 安装 Python 扩展（发布者是 Microsoft，扩展市场搜 "Python" 即第一个）
2. 打开项目文件夹后，`Ctrl+Shift+P` → `Python: Select Interpreter` → 选 `.venv` 里的那个解释器
3. 断点调试：行号左侧点红点，F5 启动——用起来和 IDEA 调试 Java 一样

**Jupyter（本课只需知道是什么）**：笔记本 = 代码单元 + 富文本 + 输出图表，全部存进一个 `.ipynb` 文件（本质是 JSON）。ML 教程、Kaggle 比赛、论文实验几乎全用它——因为可以只重跑某一个单元，调参试错极快。VS Code 原生支持打开 `.ipynb`。本阶段刻意用 `.py` 练工程手感，后续阶段再用 notebook。

## 练习

1. 验证环境：确认 `python3 --version` ≥ 3.10、`uv --version` 正常输出。提示：装完 uv 后重开终端。
2. 用 venv 和 uv 各创建一个虚拟环境，分别安装 numpy，用 `pip list` / `uv pip list` 对比。提示：不激活环境直接 pip install 会装到全局——注意提示符。
3. 写 `hi.py`：用 `input()` 读入名字，用 f-string 打招呼；分别以 `python3 hi.py` 和 `./hi.py` 两种方式执行。提示：第二种需要 shebang + chmod +x。
4. 在 REPL 里依次计算 `2**10`、`10/3`、`10//3`、`10%3`，并用 `type(结果)` 查看类型。提示：`**` 是幂，`//` 是整除。

## 小结与自测

1. Python 与 Java 执行模型的最大差异？—— 无独立编译阶段，字节码即时生成即时解释，类型检查推迟到运行时。
2. 为什么每个项目要独立虚拟环境？—— 依赖版本互相隔离，避免全局 site-packages 冲突，类似 Maven 每项目独立依赖树。
3. 激活 `.venv` 前后的区别是什么？—— PATH 前插入了 `.venv/bin`，python3/pip 指向该环境内的副本。
4. REPL 适合干什么？—— 快速验证语法与 API 返回值，零成本试错（相当于常驻的 jshell）。
5. Jupyter 和 .py 怎么取舍？—— 探索实验用 notebook，工程代码用 .py；本阶段以 .py 为主。
