# 第 6 课：模块、包与环境管理

> 🎬 开场钩子：一个反直觉事实：Python 的 `import` 不只是「引入命名空间」——它会把你导入的那个文件从头到尾**执行一遍**。如果模块顶层写着 `print("hi")`，它第一次被 import 时就真的会打印出来。Java 的 import 只是给编译器指路，Python 的 import 是「加载并运行」，这背后的机制正是本课第一站。

⏱ 建议学时：1 小时

## 本课目标

1. 说清 import 的真实含义：找到模块 → **执行其顶层代码** → 缓存；不是 Java 的「只引入命名空间」
2. 准确解释 `if __name__ == "__main__":` 的判定逻辑
3. 能组织一个多文件包结构并正确相互 import
4. 掌握 pip/uv 常用命令，看懂 requirements.txt 与 pyproject.toml
5. 速览高频标准库：pathlib / json / os / datetime / collections

## 6.1 一个 .py 文件就是一个模块

`train.py` 里的顶层代码（函数、类、变量）构成一个命名空间；`import train` 之后用 `train.某名字` 访问。

四种 import 姿势：

```python
import math                        # 全名访问：math.sqrt(2)
import numpy as np                 # 起别名（约定俗成，全员都这么写）
from math import sqrt, pi          # 引入具体名字：sqrt(2) 直接用
from math import sqrt as root      # 引入并改名
# from math import *               # 禁用：污染命名空间，不知道名字哪来的
```

关键机制：**模块第一次被 import 时，其顶层代码会被从头到尾执行一遍**，然后缓存在 `sys.modules`。之后再 import 直接命中缓存，不会重复执行。

> ☕ Java 视角：Java 的 import 只是给编译器指路，类体不会因此「跑起来」。Python 的 import 是「加载 + 执行」：如果模块顶层有 `print("hi")`，每次进程里第一次 import 都会打印。这也解释了为什么顶层代码要克制——重活全部包进函数和类里。

## 6.2 `__name__ == "__main__"` 的准确含义

每个模块都有内置变量 `__name__`：

- 被**直接运行**（`python3 train.py`）时，该模块的 `__name__` 是字符串 `"__main__"`
- 被**别人 import** 时，`__name__` 是模块名（如 `"train"`）

于是惯用法诞生：

```python
def main():
    ...

if __name__ == "__main__":     # 只有作为入口直接跑时才执行
    main()                     # 被别人 import 时，只暴露函数定义，不产生副作用
```

> ☕ Java 视角：相当于把「public static void main」从语言机制降级为社区约定——文件永远可以被 import 复用，同时保留「当入口跑」的能力。本课程所有示例代码都遵循这个结构，你的 todo.py 也应如此。

## 6.3 包：目录形式的模块集合

带 `__init__.py` 的目录是包（package），目录层级即模块路径：

```
mlproj/
├── pyproject.toml
├── mlproj/
│   ├── __init__.py        # 存在即标志「这是一个包」
│   ├── data.py
│   ├── model.py
│   └── utils/
│       ├── __init__.py
│       └── metrics.py
└── tests/
    └── test_data.py
```

在项目根目录运行时：

```python
from mlproj.data import load_dataset          # 绝对导入（推荐）
from mlproj.utils.metrics import accuracy

from .data import load_dataset                # 相对导入：包内部用（一个点=当前包）
```

注意：运行入口脚本尽量放在项目根目录（或用 `uv run`），否则相对导入会报错。`__init__.py` 可以为空，也可写「包被导入时执行的初始化」。

> ☕ Java 视角：目录结构即包名这点像 Java 的 package，但没有 public/package-private 的访问控制，一切靠约定。Java 一文件一公共类，Python 一文件（模块）里装多少类随意，按「一个内聚主题一个模块」组织。

## 6.4 依赖管理：pip、uv、requirements.txt、pyproject.toml

**pip 常用命令**（在激活的虚拟环境里）：

```bash
pip install numpy              # 安装
pip install "numpy>=1.26"      # 带版本约束
pip install -r requirements.txt   # 按清单批量装
pip list                       # 已装列表
pip freeze > requirements.txt  # 导出当前环境精确版本（复现用）
pip uninstall numpy
```

**uv 常用命令**（本课程默认）：

```bash
uv venv                        # 创建 .venv
uv pip install numpy           # pip 接口的极速版
uv pip install -r requirements.txt
uv pip list

# 项目模式（推荐用于正经项目）：
uv init                        # 生成 pyproject.toml
uv add numpy matplotlib        # 声明依赖 + 装包 + 更新 uv.lock
uv remove numpy
uv sync                        # 按 uv.lock 精确还原环境
uv run python mlproj/train.py  # 在项目环境中运行（免激活）
```

**两份文件的分工**：

```toml
# pyproject.toml —— 项目元数据 + 依赖声明（你要写的）
[project]
name = "mlproj"
version = "0.1.0"
requires-python = ">=3.10"
dependencies = [
    "numpy>=1.26",
    "matplotlib>=3.8",
]
```

`requirements.txt` 是更早的简单格式：一行一个包，常配合 `pip freeze` 导出精确版本做复现。`uv.lock` / `requirements.txt`（freeze 版）锁的是「解析结果」，pyproject.toml 声明的是「意图」。

> ☕ Java 视角：pyproject.toml ≈ pom.xml / build.gradle；PyPI ≈ Maven Central；uv.lock ≈ 锁定版本的依赖快照；`uv add` ≈ 在 pom 里加 dependency 并自动装好。差异：Python 没有传递依赖的 scope 体系，环境靠虚拟环境隔离而不是仓库本地缓存。

> 🍿 彩蛋｜一场迁延十余年的升级：Python 2 到 3 故意不兼容，社区整整迁移了十来年，直到 2020 年 Python 2 才正式停止维护。所以你才会看到 pyproject.toml 里 `requires-python = ">=3.10"` 这样的门牌——吃过亏的生态，学会了把版本要求写在最显眼处。

## 6.5 常用标准库速览

不用装任何东西，随 Python 附带。ML 日常高频：

| 库 | 干什么 | 高频 API |
|---|---|---|
| `pathlib` | 面向对象文件路径（优先用它，别拼字符串） | `Path("a")/"b"`、`.read_text()`、`.write_text()`、`.exists()`、`.mkdir(parents=True, exist_ok=True)`、`.glob("*.csv")`、`.stem` |
| `json` | JSON ↔ dict/list 互转 | `json.dumps(obj)`（转字符串）、`json.loads(s)`（解析）、`json.dump/load`（带 f 直接对文件） |
| `os` | 进程环境与系统交互 | `os.environ.get("CUDA_VISIBLE_DEVICES")`、`os.getcwd()`；老路径函数 os.path 已被 pathlib 取代 |
| `datetime` | 日期时间 | `datetime.now()`、`.strftime("%Y-%m-%d %H:%M")`、`.strptime()`、`timedelta(hours=1)` 做加减 |
| `collections` | 增强容器 | `Counter`（计数）、`defaultdict`（缺键自动建默认值）、`deque`（双端队列） |

其余知道名字即可，用到再查：`random`、`math`、`itertools`（排列组合与迭代工具）、`functools`（缓存 lru_cache、partial）、`re`（正则）、`sys`（argv/路径/退出码）、`typing`（类型工具）。

十五分钟演示（json + pathlib + datetime + collections 组合拳）：

```python
# tools_demo.py —— 标准库组合演示
import json
from collections import Counter
from datetime import datetime, timedelta
from pathlib import Path


def main() -> None:
    log_dir = Path("logs")
    log_dir.mkdir(exist_ok=True)               # 已存在也不报错

    record = {"time": datetime.now().isoformat(timespec="seconds"),
              "loss": 0.4132}
    path = log_dir / "run.json"                # 用 / 拼路径，跨平台
    path.write_text(json.dumps(record, indent=2), encoding="utf-8")
    print(path.read_text(encoding="utf-8"))    # 回读打印

    loaded = json.loads(path.read_text(encoding="utf-8"))
    ts = datetime.fromisoformat(loaded["time"])
    print(f"记录时间 +1 天 = {ts + timedelta(days=1)}")

    words = "the quick the lazy the dog".split()
    print(Counter(words).most_common(2))       # [('the', 3), ('quick', 1)]


if __name__ == "__main__":
    main()
```

> ☕ Java 视角：json 库之于 Jackson、datetime 之于 java.time、pathlib 之于 java.nio.file.Paths——但全部零依赖、开箱即用。Counter 和 defaultdict 是 Java 集合框架没有的「统计利器」，写评估脚本时你会天天用 defaultdict(list) 做分组。

## 练习

## 小结与自测

1. import 一个模块时发生了什么？—— 定位 → 执行其顶层代码一次 → 缓存进 sys.modules，后续 import 命中缓存。
2. `__name__` 何时等于 `"__main__"`？—— 该文件作为入口被直接运行时；被 import 时是模块名。
3. pyproject.toml 与 requirements.txt 的区别？—— 前者是项目元数据+依赖声明（意图），后者是包清单（常为 freeze 出的精确版本，用于复现）。
4. pathlib 相比字符串拼路径的优势？—— 跨平台分隔符、面向对象链式操作、自带读写与遍历方法。
5. Counter 与 defaultdict 各解决什么？—— 计数免判空；缺键时自动构造默认容器（分组惯用法）。
