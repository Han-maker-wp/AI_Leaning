## 1.1 什么是机器学习：从「写规则」到「学规则」

先看你熟悉的世界。假设要写一个垃圾邮件过滤器，Java 的做法：

```java
// 规则由人写死：if 正文包含"中奖" && 发件人不在通讯录 -> 垃圾
// 规则引擎越来越庞大，每条规则都要人维护，且道高一尺魔高一丈
```

机器学习的做法：**准备几万封标注好的邮件（垃圾/正常），让算法从数据里自己拟合出规则**。规则不再以 if-else 存在，而是以几百万个浮点数（参数）存在——你写的是「学习的过程」，不是「学习的结果」。

> ☕ Java 视角：传统开发是 `规则 + 数据 → 答案`（程序就是规则）；机器学习是 `数据 + 答案 → 规则`（程序产出规则）。写 if-else 时你在当领域专家，写 ML 时你在当「让算法当领域专家」的工程师。这也是为什么 ML 项目的核心资产常常不是代码而是数据。

一个贯穿始终的公式（现在记住字面，后面每课都在填肉）：

```
模型 = 一个带参数 w 的函数 y = f(x; w)
训练 = 根据「预测与真值的差距」反复调整 w
```

## 1.2 三大范式：监督、无监督、强化

| 范式 | 数据形态 | 回答的问题 | 例子 |
|---|---|---|---|
| 监督学习 | (输入 x, 标签 y) 成对样本 | x → y 的映射是什么 | 垃圾邮件分类、房价预测 |
| 无监督学习 | 只有 x 没有 y | 数据本身有什么结构 | 用户聚类、降维可视化 |
| 强化学习 | 环境 + 奖励信号 | 什么动作序列让长期奖励最大 | 下棋、机器人控制、RLHF 对齐 |

本阶段与你的最终目标（微调 LLM）几乎全部落在**监督学习**；无监督了解概念即可；强化学习在 LLM 语境下会以 RLHF/偏好对齐的形式重现，届时再展开。

监督学习再分两支：输出是离散类别叫**分类**（垃圾/正常），输出是连续数值叫**回归**（房价）。注意：「逻辑回归」名字带回归，实际是分类算法（第 4 课揭晓为什么叫这个名字）。

## 1.3 特征与标签：数据的行话

以垃圾邮件为例，一条数据叫一个**样本（sample）**：

- **特征（feature）**：描述样本的数值输入。比如「正文长度」「链接数」「中奖 出现次数」。习惯把一个样本的特征排成向量 x ∈ R^d，把 n 个样本叠成矩阵 X ∈ R^{n×d}——这就是阶段 0 第 7 课的 `(n, d)`
- **标签（label/target）**：要预测的答案 y。垃圾=1/正常=0
- **模型（model）**：f(x; w)，机器学出来的「规则」
- **参数（parameter）**：w，训练要调整的数。深度学习里的「大模型」大到几十亿参数，但本质仍是这一组 w

> ☕ Java 视角：把 X 想象成一张宽表：一行一个样本、一列一个特征、外加一列 label——和你每天打的 SQL 表结构一一对应。特征工程（第 6 课）就是把原始数据洗成这张表的过程。

## 1.4 训练/验证/测试集：为什么必须切分

标准做法：把数据切成三份（常见 6:2:2 或小数据 8:1:1）：

- **训练集**：给算法「学习」用——上课的习题
- **验证集**：调超参数、选模型用——模拟考，可以考多次
- **测试集**：最终评估一次——高考，考完不许再改志愿

为什么必须切？核心矛盾：**在训练集上的表现好不等于泛化好**。模型完全可以「背下」训练样本（过拟合，第 5 课主角），你必须要一份「没见过」的数据来检验。用考试类比：只用做过的原题评估学生，测出的是记忆力不是能力。

两条纪律：

1. 测试集只在最后碰一次。反复「看测试集 → 调模型 → 再看」= 把高考题当模拟考刷，成绩虚高
2. **数据泄漏（data leakage）**：任何「训练时不该知道的信息」混进了训练过程（比如用全量数据算标准化参数再切分）都会让评估虚高。第 6 课 Pipeline 就是为了防它

## 1.5 五分钟跑通第一个 sklearn 程序

环境：`uv pip install scikit-learn`。经典鸢尾花（iris）数据集：150 个样本、4 个特征（花萼/花瓣的长宽）、3 类鸢尾花。

```python
# first_sklearn.py —— 第一个 sklearn 程序：鸢尾花分类
from sklearn.datasets import load_iris
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score
from sklearn.model_selection import train_test_split


def main() -> None:
    iris = load_iris()
    X, y = iris.data, iris.target          # X:(150,4)  y:(150,)
    print(X.shape, y.shape)                # 先看形状：150 个样本、4 维特征

    X_train, X_test, y_train, y_test = train_test_split(
        X, y, test_size=0.3, random_state=42, stratify=y,
    )   # stratify=y：切分后各类比例与整体一致（分类任务标配）

    model = LogisticRegression(max_iter=200)
    model.fit(X_train, y_train)            # 训练：从数据学参数 w
    y_pred = model.predict(X_test)         # 预测：用学到的 w 算新样本

    acc = accuracy_score(y_test, y_pred)   # 准确率：预测对的比例
    print(f"测试集准确率：{acc:.4f}")


if __name__ == "__main__":
    main()
```

五分钟里发生的所有事，就是本阶段的完整路线图：

- `train_test_split` → 第 1 课的切分纪律
- `model.fit` 内部 → 第 2、3 课的损失函数与梯度下降（逻辑回归 + 交叉熵）
- `accuracy_score` → 第 4 课会说准确率远远不够
- 效果不好怎么办 → 第 5 课过拟合诊断
- 换模型/做工程化 → 第 6 课 Pipeline 与树模型

> ☕ Java 视角：fit/predict 是一个约定接口（sklearn 称 estimator 范式）：所有模型——逻辑回归、决策树、随机森林——都实现这两个方法。这就是面向接口编程：换算法 = 换实现类，上下游代码零改动，策略模式既视感。与 Java 世界的区别是契约靠文档与鸭子类型（阶段 0 第 5 课）维系，没有 interface 关键字。

> 🍿 彩蛋｜ML 界的传家宝：鸢尾花（iris）数据集由统计学家 Fisher 在 1936 年发表——比电子计算机的普及还早。近百年过去，无数论文和教程的第一行模型代码仍在跑这 150 朵花，它堪称机器学习的「Hello, World」。

## 1.6 ML 项目的生命周期（对照你熟悉的 Web 开发流程）

> ☕ Java 视角：Web 项目的节奏是「需求 → 表设计 → 开发 → 测试 → 上线 → 迭代」，需求相对确定、逻辑由你写。ML 项目多了一个「实验循环」，且正确性以指标而非断言衡量：

| Web 开发 | ML 项目 | 关键差异 |
|---|---|---|
| 需求评审 | 问题定义：这题是分类还是回归？指标选什么？ | 指标定错，后面全白干 |
| 表结构设计 | 数据收集 + 特征工程 | 数据质量 = 上限 |
| 写业务逻辑 | 选模型 + 训练调参 | 逻辑是「学」出来的，不是写的 |
| 单元测试/集成测试 | 留出验证/测试集评估 | 评估是统计结论，不是确定性通过 |
| 上线部署 | 部署 + 监控（数据漂移） | 数据分布会变，模型会悄悄变差 |
| 迭代新需求 | 换数据重训 / 调超参 | 实验记录（改了什么、结果如何）就是工程资产 |

两个职业习惯提前养成：**每次实验固定随机种子并记录超参数**（否则结果不可复现，等于白做）；**改动一次只改一个变量**（否则无法归因）。这两条在后面微调 LLM 时是硬纪律。

## 练习

1. 把 `test_size` 改成 0.2 与 0.4，`random_state` 换三个值，观察准确率波动并解释。提示：150 个样本很少，切分随机性会显著影响结果。
2. `print(iris.DESCR)` 阅读数据集说明，回答：多少样本、多少特征、3 个类别名是什么。提示：load_iris 返回的 Bunch 对象还带 feature_names/target_names。
3. 思考题：垃圾邮件过滤里，特征与标签各是什么？想加「发件域名信誉」这个特征，需要做什么。提示：特征必须是把原始信息数值化后的列。
4. 指出哪种做法构成数据泄漏：A) 用全部数据做标准化后切分；B) 切分后只用训练集拟合标准化参数。提示：谁的信息在训练前被「看过」。

## 小结与自测

1. 机器学习与传统规则开发的本质区别？—— 数据+答案 → 学出规则（参数），而非人写死规则。
2. 三大范式各举一例？—— 监督（分类/回归）、无监督（聚类）、强化（游戏 AI）。
3. 为什么需要验证集而不能直接用测试集调参？—— 反复看测试集等于信息泄漏，评估虚高。
4. X 与 y 的形状约定？—— X:(n_samples, n_features)，y:(n_samples,)。
5. fit/predict 范式像 Java 的什么？—— 面向接口编程：估算器接口统一，模型可插拔替换。
