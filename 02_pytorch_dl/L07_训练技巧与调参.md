# 第 7 课：训练技巧与调参

## 本课目标

2. 理解早停思想并实现简版；

## 7.1 先会诊断：读曲线

三种典型形态（纵轴 loss，横轴 epoch）：

```
欠拟合：                    过拟合：                        刚好：
train ████▁▁ 高位持平       train ▁▁▁▁▁↓ 一路降           train ▁▁▁▁↓
val   ████▁▁ 高位持平       val   ▁▁▄▄▆▆ 先降后升 ←分叉   val   ▁▁▁▁↓ 贴着 train
→ 容量不足/训练不够         → 开始背训练集                  间距小且双双收敛
```

要点：**必须有验证集才能诊断**。train loss 永远会降（模型容量够就会记住训练集），泛化能力只有没见过的数据能告诉你。切分方式：

```python
from torch.utils.data import random_split

train_set, val_set = random_split(
    full_train_set, [55000, 5000],
    generator=torch.Generator().manual_seed(42),   # 固定种子，保证实验可复现
)
```

对策速查：过拟合（按顺序试）——更多数据/数据增强、正则化（weight decay、dropout）、减小模型、早停；欠拟合——加大模型、训练更久、检查 lr 是否过小。

## 7.2 学习率调度

直觉：训练初期离最优远，大步快走；后期在谷底附近，大步会跨来跨去，小步精修。调度器（scheduler）在训练中自动调整 lr。

两种常用（都在 `torch.optim.lr_scheduler`）：

```python
from torch.optim.lr_scheduler import StepLR, CosineAnnealingLR

scheduler = StepLR(optimizer, step_size=3, gamma=0.5)
# 每 3 个 epoch lr 乘 0.5：阶梯下降，简单粗暴，适合粗调

scheduler = CosineAnnealingLR(optimizer, T_max=10)
# lr 按余弦曲线从初值平滑降到接近 0（T_max 通常 = 总 epoch 数）
# 后期自动「精修」，是深度学习的默认审美
```

用法三行：

```python
for epoch in range(EPOCHS):
    train_one_epoch(...)          # 内部每个 batch 调 optimizer.step()
    val_loss = evaluate(...)
    scheduler.step()              # 每个 epoch 一次，且在 optimizer.step() 之后
```

两个易错点：

1. `scheduler.step()` 是**每个 epoch** 调一次，`optimizer.step()` 是**每个 batch** 调一次；顺序上 scheduler 在后。搞反会有警告且语义错。
2. 「恢复训练」的 checkpoint 应把 scheduler 状态一并保存（教学场景可忽略）。

## 7.3 早停

思想：val loss 开始回升说明开始过拟合，那就在「最好的那一刻」停下，并保留那份最好的权重。实现只需三样：patience（容忍几个 epoch 不改善）、best 记录、停机判断：

```python
best_val, patience, bad_epochs = float("inf"), 3, 0
for epoch in range(EPOCHS):
    train_one_epoch(...)
    val_loss = evaluate(...)
    if val_loss < best_val:                  # 改善：记录并保存当前权重
        best_val, bad_epochs = val_loss, 0
        torch.save(model.state_dict(), "best.pt")
    else:                                    # 不改善：计数 +1
        bad_epochs += 1
        if bad_epochs >= patience:
            print(f"early stop at epoch {epoch}")
            break

model.load_state_dict(torch.load("best.pt"))  # 回滚到历史最佳权重
```

早停是免费的防过拟合手段（不动任何模型结构），代价只是要留出验证集。

## 7.4 checkpoint 保存与加载

核心 API 是 `state_dict()`：把模型所有参数导出为「名字 → tensor」的有序字典。

```python
# 保存（推荐：只存 state_dict）
torch.save(model.state_dict(), "model.pt")

# 加载：先建同结构模型，再灌入参数
model = TwoLayerMLP(784, 128, 10)
model.load_state_dict(torch.load("model.pt"))
model.eval()   # 推理前记得切模式
```

☕ Java 类比：`state_dict` 像**只序列化字段值**的 POJO 快照——存的是「这层权重是多少」这种纯数据；反序列化时类结构（你的代码）已经在工程里，对上字段名就灌回去，跨版本最稳。PyTorch 也允许 `torch.save(model)` 存整个对象，但那像 Java 序列化整个对象图：把类引用也 pickle 进文件，代码一改就崩，官方不推荐。**存数据、不存代码**——工程上永远更稳。

要「恢复训练」而不只是恢复权重，checkpoint 应包含 optimizer 状态（Adam 的动量）、epoch、最佳指标。惯例存 dict：

```python
torch.save({
    "epoch": epoch,
    "model_state": model.state_dict(),
    "optimizer_state": optimizer.state_dict(),
    "best_val": best_val,
}, "ckpt.pt")

ckpt = torch.load("ckpt.pt")
model.load_state_dict(ckpt["model_state"])
optimizer.load_state_dict(ckpt["optimizer_state"])
```

另注：PyTorch 2.6 起 `torch.load` 默认 `weights_only=True`（只允许纯张量数据，更安全）。加载上述纯参数文件不受影响；遇到要加载含自定义对象的老文件时，按报错提示处理。

## 7.5 调参优先级：lr > 结构 > 其他

调参时间有限，经验上的优先级：

1. **学习率**：影响最大。太大 loss 发散/nan，太小几分钟不动。方法：从 1e-3（Adam）或 0.1（SGD）出发看曲线，以 3~10 倍步长做数量级扫描（0.1 / 0.01 / 0.001）。
2. **模型结构 / 容量**：宽一点/深一点、加正则（dropout、weight decay）。参数量与数据量要匹配（几万样本配几十万参数量级，不是几千万）。
3. **batch_size / epoch 数**：batch 32/64 起步；epoch 配合早停，不用猜。
4. **其他**（初始化、调度器细节、激活函数选择……）：前三个没调好前不值得碰。

一次只改一个变量，否则说不清哪个改动起效——科学实验的控制变量法，也是 Checkpoint 三组对比实验的要求。

> 🍿 彩蛋｜JVM 调参既视感：超参数 vs 参数，就像 JVM 参数 vs 堆里对象——`-Xmx4g` 是你启动前设的（超参数），运行期的对象是程序自己「长」出来的（参数）。调参优先级这套打法，和你当年调 JVM 的直觉一模一样：先动影响最大的那个。

## 7.6 Adam vs SGD

- **SGD**：沿负梯度方向走固定步长（`lr × grad`）。简单，收敛轨迹噪声大；配 momentum（动量：累计历史梯度方向）后在 CV 里常调出更好泛化，但吃调参功力。
- **Adam**：为每个参数自适应步长——维护梯度的一阶矩（均值）与二阶矩（方差）估计，梯度大的参数收步子、梯度小的放大，相当于自动「按参数调 lr」。对 lr 不那么敏感，默认起步首选，`lr=1e-3`。
- **AdamW**：Adam + 解耦 weight decay（正则），Transformer / BERT 系标配（第 3 阶段微调就用它）。

选型经验：教学与快速实验用 Adam；比赛/论文级调优可试 SGD+momentum；微调预训练模型一律 AdamW。数学细节（动量更新式）见 d2l（zh.d2l.ai）优化算法章节，现阶段掌握「何时用哪个」即可。

## 小结与自测

1. 过拟合在曲线上怎么看？
   答：train loss 继续降、val loss 回升，两线分叉。
2. scheduler.step 与 optimizer.step 的区别？
   答：后者每 batch 更新参数；前者每 epoch 调整 lr，且在后者之后调用。
3. 为什么存 state_dict 而不存整个 model 对象？
   答：state_dict 是纯参数数据、与代码解耦；整个对象 pickle 绑定类定义，代码一改就崩。
4. 早停的 patience 是什么？
   答：容忍 val 指标连续多少个 epoch 不改善才停机。
5. 调参第一优先级？
   答：学习率，做数量级扫描最有效。
