# 第 1 课：分词与词向量

> 🎬 开场钩子：2013 年，word2vec 抛出一个让所有人愣住的结果：词可以做算术——「国王 − 男 ＋ 女 ≈ 女王」。在向量空间里，性别是一个方向，王位是一个位置，语义第一次变得可计算。而这一切的起点，是今天这节课要回答的第一个问题：怎么把一个词变成一串数字？

⏱ 建议学时：2 小时

## 本课目标

1. 能说清中文与英文分词难点的差异；
2. 能按主线复述词袋 → TF-IDF → 词嵌入的思想演进（每一步解决上一步的什么问题）；
3. 理解分布假说与 word2vec（skip-gram）的训练直觉；
4. 能解释「embedding 就是查表」并验证 one-hot × 矩阵 = 查一行；
5. 会用 torch.nn.Embedding 构建查表并计算 cos 相似度。

## 1.1 分词为什么难

模型吃的是数字，第一步必须把文本切成 token（词/子词/字符）再映射为 id。这一步比想象中难：

- 英文：天然空格分隔，但 `"New York"` 是一个词还是两个？`"don't"` 怎么切？
- 中文：没有分隔符。经典歧义：「研究生命的起源」可以切成「研究 / 生命 / 的 / 起源」或「研究生 / 命 / 的 / 起源」。词典再大也总有没见过的词（OOV：人名、新造词、错别字）。
- 折中方案：子词（subword）。把生僻词拆成常见片段（如 BPE 把 unhappiness 拆成 un / happi / ness），词表可控、OOV 消失。BERT / GPT 都用子词，第 6 课会实际操作 tokenizer。

本课先假设「token 已切好」，聚焦下一个问题：每个 token 用什么数字表示？

## 1.2 词袋（Bag of Words）：有字无义

最古老的方案：词表大小 V，每个句子表示成长度 V 的计数向量。

```
词表: ["猫", "追", "狗"]
"狗追猫" -> [1, 1, 1]
"猫追狗" -> [1, 1, 1]     # 完全相同！
```

两个致命伤：丢掉语序（上例两句意思相反、向量相同）；向量稀疏且高维（V 可达十万）。TF-IDF 改进的是权重——出现太频繁的虚词（的、是）降权，本句出现但全局稀有的词升权——在搜索引擎时代立过大功，但仍是稀疏计数向量，依然「没有语义」：无法计算「猫」和「狗」的关系，它们只是词表里两个不同的下标。

## 1.3 思想跃迁：让语义可计算

分布假说（distributional hypothesis）：**一个词的含义由它的上下文决定**。「国王」总与「王后、王国、统治」共现，「苹果」总与「吃、手机、水果」共现——即使不懂中文，统计共现也能区分它们。

于是目标变成：给每个词学一个**稠密的低维向量**（如 300 维），让「上下文相似的词，向量也相似」。这样的向量叫词嵌入（word embedding）。「嵌入」= 把离散符号（词）放进连续空间。

语义空间里还能做算术（word2vec 的著名结果）：

```
vector(国王) - vector(男) + vector(女) ≈ vector(女王)
```

方向承载语义关系。这不是硬编码的规则，是从语料中学出来的——机器第一次在统计意义上「理解」了词义。

## 1.4 word2vec：skip-gram 的直觉

word2vec（2013）的 skip-gram 模式：**用中心词预测上下文**。句子「我 爱 自然 语言 处理」取「语言」为中心词，窗口 2 内的上下文是 {自然, 处理}。做法：

1. 每个词配两个向量：作为中心词的 v、作为上下文的 u；
2. 训练目标：最大化 P(上下文词 | 中心词)，等价于在语料上滑动窗口做海量「小分类」；
3. 训练完丢掉 u，留下 v 作为词向量。

不必推目标函数（负对数似然 + 对全词表的 softmax），记住核心洞察：**为完成「预测上下文」而学的参数，恰好编码了词义**——分布假说保证「上下文分布 ≈ 词义」。这与后面一切预训练一脉相承：BERT 的完形填空、GPT 的预测下一词，都是「设一个要用上下文的任务，逼模型把语义压进参数」。

> 🍿 彩蛋｜word2vec 的余波：2013 年的 word2vec 出自 Mikolov 之手，他后来去了 Facebook。而「向量做算术」那个名场面，从此成了几乎所有词向量教程的开场白——包括这一篇。

## 1.5 embedding 是查表：one-hot × 矩阵

设词表 V=5 万、嵌入维度 d=300，参数是一个矩阵 E ∈ R^{V×d}。取第 i 个词的向量：

```
onehot(i) ∈ R^V        （只有第 i 位是 1）
onehot(i) @ E = E 的第 i 行
```

one-hot × 矩阵 = 查表，所以实现上根本不存 one-hot、不做乘法，直接 `E[i]`。验证（完整可运行）：

```python
import numpy as np

if __name__ == "__main__":
    V, d = 5, 3
    E = np.arange(V * d).reshape(V, d).astype(float)   # 假装这是学到的词向量表

    i = 2
    onehot = np.zeros(V)
    onehot[i] = 1.0
    print(onehot @ E)      # [6. 7. 8.]
    print(E[i])            # [6. 7. 8.]  —— 完全一样：one-hot 乘矩阵就是查第 i 行
```

「乘 one-hot = 选择」这个代数事实，把离散 id 世界与连续向量世界连接了起来。

> 🍿 彩蛋｜查表是老本能：one-hot × 矩阵＝查第 i 行，对 Java 老兵就是熟悉的抉择——`map.get(key)` 还是拿 id 当下标直接进数组。乘法贵、寻址便宜，能查表就不做乘法：性能调优的老道理，在这里原样成立。

## 1.6 torch.nn.Embedding：查表的工程化

`nn.Embedding(num_embeddings=V, embedding_dim=d)` 内部就是那个可学习矩阵 E，forward 接收整数 id 张量、输出对应行：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

if __name__ == "__main__":
    torch.manual_seed(0)
    vocab = {"我": 0, "爱": 1, "机器": 2, "学习": 3}
    V, d = len(vocab), 4

    emb = nn.Embedding(V, d)
    for name, p in emb.named_parameters():
        print(name, tuple(p.shape))       # weight (4, 4)：只有一个参数矩阵

    ids = torch.tensor([vocab["我"], vocab["爱"]])   # [2]
    vecs = emb(ids)                                  # [2, 4]：每个 id 查一行
    print(vecs.shape)
    print("等价于直接索引:", torch.equal(emb(ids), emb.weight[ids]))   # True

    # 一个批句子（已补齐到等长）: [batch=2, seq=3]
    batch_ids = torch.tensor([[0, 1, 2], [3, 1, 0]])
    print(emb(batch_ids).shape)                      # [2, 3, 4] -> [batch, seq, dim]

    # 语义相似度：cos（只看方向、与向量长度无关）
    a, b = emb(torch.tensor(0)), emb(torch.tensor(1))
    print(F.cosine_similarity(a, b, dim=0).item())   # 随机初始化时无语义，训练后才有意义
```

三个要点：

- 输入形状任意 `[...]`，输出形状 `[..., d]`——id 换成向量、其余维度不变。这是所有语言模型的第一层；
- cos 相似度 = a·b / (|a||b|)，衡量方向是否一致，是语义相似度的标准度量（点积受向量长度影响，cos 不受）；
- 随机初始化的 embedding 没有语义，必须训练（或从预训练模型加载，第 5~7 课见）。

## 1.7 与后续课程的关系

- 第 2、3 课（RNN / Attention）的输入都是 embedding 序列 `[batch, seq, d]`；
- 第 6 课的 tokenizer 输出 id 序列，进模型第一件事就是查 embedding 表；
- 你 4 个月后微调的 LLM，第一层同样是 embedding。「语言模型 = embedding + 若干层变换 + 输出投影」这个骨架从本课起固定下来。

## 小结与自测

1. 词袋与 TF-IDF 的共同缺陷？
   答：稀疏计数、无语义（丢语序、词与词之间无关联）。
2. 分布假说的内容？
   答：词义由上下文决定；上下文分布相似的词语义相近。
3. skip-gram 训练什么任务？
   答：用中心词预测窗口内的上下文词；学到的中心词向量即词嵌入。
4. 为什么 embedding 等价于查表？
   答：one-hot × E 在代数上等于选出 E 的第 i 行，实现上直接索引。
5. 为什么用 cos 而不是点积衡量相似度？
   答：cos 只看方向、与向量长度无关，度量更稳定。
