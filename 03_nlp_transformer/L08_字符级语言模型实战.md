## 8.1 语言模型：一切生成的数学定义

语言模型 = 给序列分配概率的模型，链式分解为逐字符（词）的条件概率：

```
P(x_1, x_2, ..., x_n) = P(x_1) · P(x_2|x_1) · ... · P(x_n | x_1..x_{n-1})
```

只要有「下一字符分布」P(x_t | 前文)，生成就是：

```
给起始符 → 模型给分布 → 采样一个字符 → 拼回输入 → 再给分布 → ... 直到采出结束符
```

这正是第 2 课 RNN 生成、第 5 课 GPT 自回归的同一骨架。本课任务：用最简单的字符级设定（词表 = a~z 加起止符，共 27 个字符）学「英文名字的分布」并生成新名字（emma、olivia 这类味道的字符串）。

## 8.2 基线：bigram（数频次）

最简假设：下一个字符只依赖当前字符。模型 = 一张 27×27 的计数表，`P(下一个|当前)` 用频次估计：

```python
import torch

NAMES = ["emma", "olivia", "sophia", "isabella", "mia", "charlotte",
         "amelia", "harper", "evelyn", "abigail", "james", "william",
         "benjamin", "lucas", "henry", "jack", "liam", "noah", "aiden",
         "logan", "samuel", "miles", "adam", "nina", "luna"]

def build_bigram(names):
    chars = sorted(set("".join(names)))            # 26 个字母
    stoi = {s: i + 1 for i, s in enumerate(chars)}
    stoi["."] = 0                                  # '.' 同时当起始与结束符
    itos = {i: s for s, i in stoi.items()}
    N = torch.zeros(27, 27, dtype=torch.long)
    for name in names:
        ws = ["."] + list(name) + ["."]
        for c1, c2 in zip(ws, ws[1:]):             # 滑动统计相邻对
            N[stoi[c1], stoi[c2]] += 1
    P = N.float() / N.float().sum(dim=1, keepdim=True)   # 每行归一化 -> 条件分布
    return P, stoi, itos


def sample_bigram(P, itos, n=10, seed=42):
    g = torch.Generator().manual_seed(seed)
    outs = []
    for _ in range(n):
        ix, chars = 0, []
        while True:
            ix = torch.multinomial(P[ix], num_samples=1, generator=g).item()
            if ix == 0:
                break                              # 采到结束符
            chars.append(itos[ix])
        outs.append("".join(chars))
    return outs


if __name__ == "__main__":
    P, stoi, itos = build_bigram(NAMES)
    print(sample_bigram(P, itos))
```

bigram 的水平：生成的串有点像名字（相邻字母搭配频率是对的），但常出现怪异组合——它只看 1 个字符的历史，「名字开头已是 cha、下一个该配什么」它不知道。**上下文太短**是根本局限；此外它是纯查表统计，训练集没见过的前缀无法泛化。神经版解决这两点。

> 🍿 彩蛋｜bigram 就是一张赔率表：它相当于 `Map<Character, Map<Character, Double>>`——给定当前字符，查下一字符的抽签概率。没有魔法，纯数数；你马上要写的神经版，就是让这张查表「学会泛化」的升级款。

## 8.3 神经语言模型：makemore MLP

思路（Bengio et al. 2003 的经典设计，现代 LLM 的直系祖先）：用**前 3 个字符**预测下一个。架构全是已学零件：

```
3 个字符 id [B, 3]
    ↓ nn.Embedding(27, 10)           # 每个 id 查一个 10 维向量（第 1 课）
    ↓ 拼接成 [B, 30]                 # 上下文窗口摊平（reshape，第 2 课）
    ↓ nn.Linear(30, 200) + tanh      # 隐层（阶段 2 的 MLP）
    ↓ nn.Linear(200, 27)             # 输出 logits：每字符一个分数
    ↓ cross_entropy                  # = softmax + NLL，目标是真实的下一字符
```

与 bigram 的关系：把「查表统计」推广为「可泛化的函数」——上下文更长、表示连续（没见过的三连字符也能给出合理预测，因为模型学会了「相似上下文 → 相似输出」）。

```python
import torch.nn as nn
import torch.nn.functional as F

class CharLM(nn.Module):
    def __init__(self, vocab=27, emb=10, hidden=200, block=3):
        super().__init__()
        self.block = block
        self.emb = nn.Embedding(vocab, emb)
        self.fc1 = nn.Linear(block * emb, hidden)
        self.fc2 = nn.Linear(hidden, vocab)

    def forward(self, idx):                          # idx: [B, 3] 上下文字符 id
        e = self.emb(idx)                            # [B, 3, 10]
        e = e.view(e.size(0), -1)                    # [B, 30] 拼接上下文
        h = torch.tanh(self.fc1(e))                  # [B, 200]
        return self.fc2(h)                           # [B, 27] logits
```

## 8.4 训练数据构建：滑窗切片

每个名字包一层起止符，滑出全部 (上下文 3，目标 1) 样本：

```
".emma." ->  输入 [.,.,e] 目标 m；输入 [.,e,m] 目标 m；输入 [e,m,m] 目标 a；...
```

```python
def build_dataset(names, stoi, block=3):
    X, Y = [], []
    for name in names:
        ctx = [0] * block                     # 起始用 '.'(=0) 填满窗口
        for ch in name + ".":
            ix = stoi[ch]
            X.append(ctx)
            Y.append(ix)
            ctx = ctx[1:] + [ix]              # 窗口右滑一格
    return torch.tensor(X), torch.tensor(Y)
```

`[., ., e] → m` 教模型「名字常以 e 后接 m 开头」——起始 padding 让模型学到「序列开头」的分布，是 bigram 里 P(首字符) 的推广。

## 8.5 训练：又是八股文

```python
def train(model, X, Y, steps=2000, batch=32, lr=0.1, seed=42):
    g = torch.Generator().manual_seed(seed)
    opt = torch.optim.SGD(model.parameters(), lr=lr)
    model.train()
    for step in range(steps):
        ix = torch.randint(len(X), (batch,), generator=g)    # 随机小批
        xb, yb = X[ix], Y[ix]

        opt.zero_grad()                         # ① 清梯度
        logits = model(xb)                      # ② 前向
        loss = F.cross_entropy(logits, yb)      # ③ 损失
        loss.backward()                         # ④ 反向
        opt.step()                              # ⑤ 更新

        if step % 500 == 0:
            print(f"step {step:4d}  loss {loss.item():.4f}")
    return model
```

对照 bigram 的水平：bigram 查表的交叉熵约 2.5（小语料量级 2~3），神经版能压到 2.2 左右或更低——上下文从 1 字符到 3 字符的信息增益，直接体现在 loss 上。CPU 上 2000 步几秒钟，随便玩。

严谨提示：教学代码在全集上训练、没留验证集；要比较泛化请用 `random_split`（阶段 2 L07 讲过）。

## 8.6 采样生成

```python
@torch.no_grad()
def sample(model, itos, n=10, block=3, seed=42):
    model.eval()
    g = torch.Generator().manual_seed(seed)
    outs = []
    for _ in range(n):
        ctx = [0] * block
        chars = []
        while True:
            logits = model(torch.tensor([ctx]))            # [1, 27]
            probs = F.softmax(logits, dim=-1)[0]
            ix = torch.multinomial(probs, num_samples=1, generator=g).item()
            if ix == 0:
                break                                      # 结束符
            chars.append(itos[ix])
            ctx = ctx[1:] + [ix]
        outs.append("".join(chars))
    return outs
```

对比 bigram 与神经版的输出：神经版更「像名字」——3 字符上下文学到了「q 后常接 u」「e 常收尾」等更长程的规律。多换几个 seed 感受采样的随机性；temperature / top-k 等控制随机性的采样技巧，进阶阶段再学（知道名字即可）。

> 🍿 彩蛋｜「采样」不是 bug：每次生成都是从概率分布里抽签，所以同一个问题 ChatGPT 每次回答都不同——这不是不稳定，是设计。分布才是模型，采样只是从分布里摸一个样本；这句行话，从此你就听得懂了。

## 8.7 通向 GPT 的差距清单

这个约 1.4 万参数的小模型与百亿参数 GPT 的差异，逐条拆开都是已学或将学的概念：

| 差距 | 小模型 | GPT 系 |
|---|---|---|
| 上下文 | 固定窗口 3 字符、拼接 embedding | 自注意力加权聚合**全部**上下文（第 3 课），窗口数万 token |
| 表示融合 | 拼接 = 一律平等对待 | 注意力按相关性加权（该看哪看哪） |
| 架构 | 1 个隐层 | 几十层 Transformer decoder（第 4 课） |
| 词表 | 27 个字符 | 数万子词（第 1 课 BPE） |
| 数据 | 25 个名字 | 万亿 token 互联网文本 |
| 训练后 | 纯语言模型 | + 指令微调 + RLHF（对齐，后续阶段概念） |

核心的一条：**把「固定窗口拼接」换成「自注意力」，这个模型就进化成了 nanoGPT**。你在第 3 课写的那 20 行注意力，就是那把钥匙——整个 Transformer 时代的语言模型，都是本课这个骨架的工业化放大。

## 练习

1. 把 block 从 3 改成 5，观察 loss 与生成质量变化。
   提示：参数量与样本都变；小语料上收益递减甚至过拟合。
2. 给采样加 temperature：logits 除以 T 后再 softmax，对比 T=0.5 与 T=1.5。
   提示：T<1 更保守（高概率字符更突出），T>1 更随机。
3. 固定 seed，各生成 100 个名字，对比 bigram 与神经版的平均长度与「像名字率」（自定标准）。
   提示：固定 seed 保证可复现。
4. （进阶）把 CharLM 第一层换成 `nn.Linear(27, 10)` + one-hot 输入，验证与 nn.Embedding 数学等价。
   提示：第 1 课的「查表 = one-hot × 矩阵」。

## 小结与自测

1. 语言模型的链式分解式？
   答：P(x_1..x_n) = ∏ P(x_t | x_<t)；生成 = 循环采样下一 token。
2. bigram 的两条局限？
   答：只看 1 个字符历史；纯查表统计、不可泛化。
3. 神经版 CharLM 的输入输出形状？
   答：输入 [batch, 3] 字符 id，输出 [batch, 27] logits。
4. 这个模型与 GPT 的本质差距？
   答：固定窗口拼接 vs 自注意力全上下文加权（另有规模/词表/后训练差距）。
5. 起始符 padding（ctx=[0,0,0]）为什么必要？
   答：让模型学到「序列开头」的分布，并统一任意长度输入的窗口形状。
