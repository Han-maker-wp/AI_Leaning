# 第 1 课：LLM 三阶段全景——预训练、SFT、RLHF/DPO
> 🎬 开场钩子：2022 年 1 月，OpenAI 发论文说：13 亿参数的模型经过「人类反馈调教」后，人类评分赢过了 1750 亿参数的 GPT-3——小 130 倍却更受欢迎。这背后是一套三阶段流水线，今天把全图装进脑子，之后学的一切都挂在这张图上。

1. 能画出 GPT 系模型从原始文本到可用助手的**三阶段流程图**，并说出每个阶段的输入、输出、监督信号与成本量级。

## 1. 从你已经会的东西说起

你已经用 HF 微调过 BERT 分类器，这给了你一个很好的参照系。先摆清楚区别：

| | BERT（你的过去） | GPT 系 LLM（你的现在与未来） |
|---|---|---|
| 架构 | encoder-only，双向注意力 | decoder-only，因果掩码（只看左边） |
| 预训练任务 | Masked Language Modeling（完形填空） | Next Token Prediction（预测下一个词） |
| 使用方式 | 取 [CLS] 向量接分类头，输出离散标签 | 整个模型就是生成器，输出 token 序列 |
| 微调形态 | 通常全参微调，加任务头 | 主流是 PEFT（LoRA 等），不加头 |

关键转变：BERT 微调是「换头」——预训练躯干不变，换一个任务出口。LLM 微调是「教行为」——
模型出口（生成）不变，改变它在什么场景下生成什么。这个视角贯穿阶段 5。

## 2. 第一阶段：预训练（Pre-training）

### 2.1 任务定义

给定海量文本（网页、代码、书籍），把它全部切成 token 序列，训练目标只有一个：

$$\mathcal{L}_{\text{LM}} = -\sum_t \log P(x_t \mid x_{<t}; \theta)$$

「预测下一个 token」。就这么简单，简单到令人不安——但它是全部魔法的来源。

### 2.2 为什么 next token prediction 能产生「智能」

直觉：要在一个高质量语料库上把下一词预测得足够好，模型**被迫**隐式掌握：

- 语法与风格（不然续写不通顺）
- 事实知识（「中国的首都是」后面高频跟「北京」）
- 一定程度的推理（数学/代码文本中，下一步依赖于前面步骤的正确性）

预测得越准，就需要越深的「世界模型」。这不是设计出来的智能，是被压缩目标逼出来的。

### 2.3 数量级（必须建立的直觉）

| 维度 | 量级 | 备注 |
|---|---|---|
| 数据 | 万亿（T）级 token | 例如 Llama 3 约 15T、Qwen2.5 约 18T token（以各技术报告为准） |
| 算力 | 数千张加速卡，训练数周到数月 | 预训练一次成本百万美元量级 |
| 数据处理 | 清洗/去重/配比本身是系统工程 | 互联网文本 → 高质量语料的管线本身就是壁垒 |
| 产出 | **base 模型**：一个超级「自动补全」 | 不会主动听从指令 |

结论先记住：**预训练不是个人和小团队能玩的**。我们全部工作站在预训练成品的肩膀上。

> 想亲眼看一个「小预训练」长什么样：GitHub 上 Karpathy 的 nanoGPT 项目，几百行代码从零训练
> 一个字符级 GPT，是理解训练循环的最佳教材。

## 3. 第二阶段：SFT（Supervised Fine-Tuning，监督微调 / 指令微调）

### 3.1 为什么需要：base 模型「会补全」但「不听话」

你问 base 模型「中国的首都是哪里？」，它可能续写出「……这道题出现在小学地理试卷第三题」——
因为在预训练语料里，「这个问题」后面更常见的续写是**更多问题或文本**，而不是答案。
它没有错，它只是在做补全。SFT 要教的是：**遇到这种格式的输入，要输出『回答』这种格式的输出**。

### 3.2 怎么做

1. 收集高质量示范数据，典型格式：(instruction, output)，即「人类写的问题 + 人类（或强模型）写的好回答」。
2. 继续用 next token loss 训练，但**只在 output 部分计算损失**（instruction 部分不回传）——
   这一点和你微调 BERT 时「只对分类头算 loss」的思路同源：只学该学的部分。
3. 数据量级：数万到百万条高质量指令对（对比预训练的万亿 token，小了 5~7 个数量级）。

### 3.3 产出

instruct / chat 模型：多轮对话、听从指令、格式规整、知道说「我不知道」。
你在 Agent 项目里调用的所有 chat 模型，都是这个阶段之后的产品。

**本课程阶段 5 做的事，本质就是这个阶段**：拿开源 instruct 模型，用我们自建的几百到几千条
指令数据，再做一轮定向 SFT——把通用助手改造成领域专家。

## 4. 第三阶段：RLHF / DPO（对齐人类偏好）

### 4.1 SFT 的局限

很多问题存在多个「都通顺、都合理」的回答，但人类有偏好：更详细、更安全、更谦虚、不编造。
「示范数据只能给出一个好答案，无法表达『A 比 B 好』这种相对偏好」——这就是对齐阶段要注入的信号。

### 4.2 经典 RLHF 三步（InstructGPT 路线）

1. **SFT**：同上。
2. **训练奖励模型（RM）**：对同一个 prompt 采样多个回答，人类标注员排序；训练一个模型给回答打分，
   使其分数排序与人类偏好一致。本质是「把人类偏好压缩成一个可微的分数函数」。
3. **PPO 强化学习**：让 LLM 生成回答 → RM 打分 → 分数作为 reward，用 PPO 更新 LLM。
   直觉：模型「为了拿高分」学会讨好人类偏好的输出分布。

### 4.3 DPO 一句话版

DPO（Direct Preference Optimization）的洞见：可以**绕过显式的 RM 和 RL 循环**，直接从
「chosen（更好的回答）vs rejected（更差的回答）」偏好对上，用一个对比损失优化策略。
数学与工程细节留到阶段 5 L08，本课只需知道：它是当前开源社区更常用的对齐方案。

### 4.4 「对齐」对齐的是什么

三个关键词：helpful（有用）、honest（诚实）、harmless（无害）。chat 模本会拒答、会说不确定、
会追问澄清——这些「性格」不是预训练给的，是对齐阶段塑造的。

## 5. InstructGPT 论文核心发现（arXiv 2203.02155）

这篇论文是三阶段范式的出处（OpenAI，2022），三个发现必须记住：

1. **小模型 + 对齐 > 大模型 + 不对齐**：约 1.3B 参数的 InstructGPT，其输出在人类偏好评估中
   **超过了 175B 的 GPT-3 base**。对齐带来的「可用性」提升，可以跨越两个数量级的参数差距。
2. **对齐不需要天文数字的数据**：论文仅用了约 1.3 万条人工编写的 SFT 示范、约 3.3 万组偏好比较，
   就完成了对齐。对齐改的是「行为分布」，不是「知识容量」，所以数据需求小。
3. **对齐税（alignment tax）存在**：对齐后模型在部分通用 NLP 基准上可能轻微下降——
   专精一端常以另一端的小损失为代价。这个概念在阶段 5 L07（评估）会再次出现：微调后要
   「回归测试」通用能力，防止把模型调傻。

**对你的意义**：发现 1 和 2 合起来就是整个开源微调生态的理论许可证——一个小团队用 7B 模型 +
几千条好数据，就能造出在**自己领域**胜过通用大模型的助手。这正是你毕业项目要做的事。

## 6. base 模型 vs chat/instruct 模型：行为差异演示

同一段输入，两类模型的「正确打开方式」完全不同：

| 输入 | base 模型典型输出 | chat 模型典型输出 |
|---|---|---|
| `给我写一个 Java 快速排序` | 继续补全语料风格：可能接「。\n下面是归并排序的实现：」，或开始描述某博客正文 | 直接给出带解释的结构化回答 + 代码块 |
| `中国的首都是哪里？` | `中国的首都是哪里？\n1. 上海\n2. 北京…`（续写成测验题） | `中国的首都是北京。` |
| 多轮对话 | 无轮次概念，把历史当普通文本续写 | 按 role 维护对话状态 |
| 有害请求 | 无拒答机制，语料里有什么补什么 | 拒绝并解释 |

用 transformers 直观验证（典型示例，接口以官方文档为准；本地无 GPU 可用 0.5B CPU 跑）：

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

# base 版本（补全机器）与 Instruct 版本各试一次
model_id = "Qwen/Qwen2.5-0.5B"  # base；换成 "Qwen/Qwen2.5-0.5B-Instruct" 对比
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype="auto", device_map="auto")

prompt = "给我写一个 Java 快速排序"   # 注意：base 模型不套 chat template，直接喂原始文本
inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
out = model.generate(**inputs, max_new_tokens=100)
print(tokenizer.decode(out[0], skip_special_tokens=True))
```

观察重点：base 的输出「像是从某篇文档里截出来的」，instruct 的输出「像是在回答你」。

## 7. 缩放定律与涌现能力

### 7.1 缩放定律（Scaling Laws）

经验发现：在相当大的范围内，测试 loss 是**参数量、数据量、训练算力的平滑幂律函数**——
横竖都是对数坐标下的近似直线。工程意义：可以**用小模型实验外推大模型表现**，训练前就能
估算「再加多少算力能降多少 loss」。这是各大厂敢押注大模型的定量依据。

### 7.2 涌现能力（Emergent Abilities）

某些能力（多步推理、指令泛化等）在模型规模小于某阈值时接近随机水平，跨过阈值后**突变式**出现。
注意两点：

- 「涌现」的度量方式学界有争议（可能是不连续指标造成的假象），但「模型够大某能力才可用」的
  体感在工程上真实存在。
- 对你的启示：**能力看底座大小，行为看微调**。毕业项目选 Qwen2.5-1.5B/7B 作底座，能力由底座
  决定；你通过微调改变的是它在你的领域的「行为与格式」。

## 8. 我们的微调在流水线中的位置

```
[预训练]  ──万亿 token──>  base 模型          ← 不做（成本百万美元级）
[SFT]     ──数千条指令──>  领域化 instruct    ← 阶段 5 全程在这里（LoRA/QLoRA）
[RLHF/DPO] ──偏好对────>  偏好对齐的成品       ← 阶段 5 L08 选学
```

一句话总结：**我们站在巨人肩膀上，只做最后 1% 的定制**——而且这 1% 恰好是对个人价值最高的部分。

## 小结与自测

1. **Q：三阶段的监督信号分别是什么？**
   A：预训练=语料中真实的下一个 token；SFT=示范回答的 token；RLHF/DPO=人类偏好（谁更好）。
2. **Q：SFT 和预训练的损失函数有本质区别吗？**
   A：没有，都是 next token cross-entropy；区别在数据（指令对）与损失掩码（只在 response 上计算）。
3. **Q：InstructGPT「1.3B 优于 175B」中的「优」指什么？**
   A：人类偏好评估中的胜率，不是通用知识基准分数。
4. **Q：什么是「对齐税」？**
   A：对齐后模型在部分通用能力基准上轻微下降的现象；提醒我们微调后要做通用能力回归测试。
5. **Q：本课程的微调对应三阶段中的哪一环？**
   A：SFT（用 LoRA/QLoRA 低成本复刻指令微调）。
