# 第 1 课：微调全景与 LoRA 原理
> 🎬 开场钩子：2021 年，微软的研究员发现一个惊人的事实：微调一个模型，不需要动它 99.9% 的参数——在旁边挂两个小矩阵就够了。这个叫 LoRA 的思路，让「个人微调大模型」从玩笑变成了计划。你的毕业项目，就从理解它的核心公式开始。


> ⏱ 建议学时：3 小时（本课是阶段 5 的理论地基，公式要亲手推一遍）

## 本课目标

1. 能说清全参微调的三大问题：显存爆炸、灾难性遗忘、每任务一份全权重。
2. 能写出 LoRA 的核心公式 $W' = W + BA$，解释 B 零初始化/A 随机初始化、秩 $r \ll d$ 的含义。
3. 能用「内在维度/低秩假设」直觉解释：为什么一个极小的增量矩阵能改变大模型行为。
4. 能拆解 QLoRA 的三个组件（NF4 冻结主干 + LoRA 增量 + 双量化），并默写三种方式的 7B 显存对比表。
5. 能解释 lora_alpha 缩放系数的作用。

## 1. 全参微调的问题：为什么不能「像 BERT 那样」直接训

你微调 BERT 时全参更新毫无压力（BERT-base 才 1.1 亿参数）。换到 7B LLM 上，全参微调
（full fine-tuning）撞上三堵墙：

1. **显存爆炸**（阶段 4 L04 已算过）：AdamW 全参训练 ≈ 16 字节/参数 → 7B ≈ 110~120GB，
   必须多张 A100 级卡。个人玩不起。
2. **灾难性遗忘（catastrophic forgetting）**：在你的小数据集上更新**所有**权重，模型的
   通用能力会被「冲刷」——学会领域话术，忘了怎么正常聊天（症状与缓解详见 L10）。
   小数据 + 大学习率 + 全参 = 遗忘最猛组合。
3. **存储与分发负担**：每来一个任务就存一份 14GB 的完整权重，N 个任务 N 份，无法组合。

结论：我们需要「只学增量、不动主干」的微调方式——这就是 PEFT（Parameter-Efficient
Fine-Tuning，参数高效微调）的思想：**冻结预训练主干，只训练一小撮新增参数**。

PEFT 家族里你可能会遇到 prefix tuning / prompt tuning / adapter 等方法（在序列或层间加小模块），
它们各有取舍；其中 **LoRA 是当前绝对主流**，也是我们唯一要动手用的。

## 2. LoRA 原理（本课核心）

论文：LoRA: Low-Rank Adaptation of Large Language Models（arXiv 2106.09685，微软，2021）。
下一课（L03）逐节精读论文本身，本课先把原理吃透。

### 2.1 核心公式

LoRA（Low-Rank Adaptation，低秩适配）不改预训练权重 $W$，而是给目标层旁挂一个「低秩增量」：

$$W' = W + \Delta W = W + BA$$

- $W \in \mathbb{R}^{d \times d}$：冻结的预训练权重（不训练、不更新）
- $A \in \mathbb{R}^{r \times d}$：**随机初始化**（高斯），可训练
- $B \in \mathbb{R}^{d \times r}$：**零初始化**，可训练
- 秩 $r \ll d$：例如 $d = 4096$（7B 级模型的隐藏维度），$r = 8$ 或 16 即可

前向传播变为 $y = W'x = Wx + BAx$（$BAx$ 是旁路，两条路相加）。

### 2.2 三个必答的「为什么」

**Q1：为什么 B 零初始化、A 随机初始化？**
训练开始时 $\Delta W = BA = 0$（零 × 任何 = 零），模型行为与原模型**完全一致**——微调从
「原点」出发，不会一上来就破坏模型（对应你手写梯度下降的经验：初始化决定起点，起点必须在
一个好位置）。若两者都随机，$\Delta W \neq 0$，训练第一步就给模型注入了随机扰动。

**Q2：为什么低秩（小 r）就够用？——内在维度假设**
关键洞见（LoRA 论文引用的证据链）：预训练后的巨大权重矩阵已经「满能力」，适配一个新任务
所需的**改变量** $\Delta W$ 是低秩的——即它的大部分方向上几乎不变，只在少数 $r$ 个
「方向」上需要显著调整。这个「任务所需的有效自由度」被称为内在维度（intrinsic dimension）。
直觉类比：一个熟练的 Java 工程师转 Kotlin，不需要重构整个大脑，只需要在若干关键位置
「打补丁」。$r=8$ 时可训练参数量约为 7B 模型的 **0.1%~1%**，却足够改变行为。

**Q3：LoRA 挂在哪些层上？**
Transformer block 里的线性层都可以挂：注意力投影 $W_q, W_k, W_v, W_o$ 与 FFN 的
$W_{\mathrm{up}}, W_{\mathrm{gate}}, W_{\mathrm{down}}$。论文的关键实验结论（L03 详读）：
**「挂到哪些层」比「秩 r 多大」更重要**——预算固定时，把 LoRA 挂到 $W_q$ 和 $W_v$ 两处，
效果好过全挂在某一处。实践中工具链默认提供 `all`（挂所有线性层），小 r + 全挂是当前
开源社区的主流配置（阶段 5 实操即用此配置）。

### 2.3 推理时可合并：零额外延迟

$$W_{\text{merged}} = W + BA$$

训练完成后，把 $BA$ 算出来加到 $W$ 上，存成普通权重——推理图里没有任何旁路结构，
**与原模型完全同构、零额外延迟**。这是 LoRA 对 adapter 类方法（层间插入小模块，串行增加
延迟）的关键优势，也是 L09 部署课「merge_and_unload」操作的理论依据。

### 2.4 工程红利（对应全参微调三堵墙）

- 显存：不存 $W$ 的梯度与优化器状态（$W$ 冻结），只训 $BA$ → 优化器状态缩小为原来的 1%
- 遗忘：$W$ 被冻结，模型「底线」保住了，灾难性遗忘天然缓解
- 存储：每个任务只存一份几十 MB 的 $BA$ 权重；换任务换 adapter 即可

## 3. lora_alpha：缩放系数

LoRA 前向实际是：

$$y = Wx + \frac{\alpha}{r} \cdot BAx$$

- $\alpha$（lora_alpha）是超参，$\alpha / r$ 作为增量的缩放系数，**控制「补丁强度」**。
- 常见实践：$\alpha = 2r$（如 r=8、alpha=16），并在调 r 时保持 $\alpha/r$ 不变——
  这样换秩时增量输出的量级稳定，学习率不用重调。
- 直觉：$\alpha/r$ 越大，同样的 $BA$ 训练结果对输出影响越强，效果上「学得越猛」。

## 4. QLoRA：把 LoRA 的显存账打到地板

论文：QLoRA（arXiv 2305.14314，华盛顿大学，2023）。一句话：**冻结主干用 4bit 存，
LoRA 增量用 bf16 训**——训练时前向经过「反量化的主干」，反向只更新 LoRA 参数。

三个组件（对应论文标题里的关键词）：

1. **NF4 量化冻结主干**：标准 int4 的 16 个档位均匀分布，而权重分布是钟形的——NF4
   （4-bit NormalFloat）让档位按正态分布的分位点摆放，「密的地方档位密」，同样 4bit
   信息损失更小（呼应阶段 4 L04 的量化直觉）。
2. **双量化（Double Quantization）**：量化本身需要存每组的缩放常数（缩放因子本身也占
   显存），把这些常数再量化一次，每参数再省约 0.4 bit——小钱也抠，积少成多。
3. **分页优化器（Paged Optimizers）**：显存峰值时把优化器状态临时换页到内存，防止长序列
   时的 OOM 尖峰（工程兜底手段）。

### 7B 显存构成对比表（默写级，数字来自阶段 4 L04 的推导）

| 方式 | 主干权重 | 梯度 | 优化器状态 | 激活等 | 合计量级 | 硬件门槛 |
|---|---|---|---|---|---|---|
| 全参（AdamW 混合精度） | 14 GB | 14 GB | ≈84 GB | 数 GB | **≈110~120 GB** | 多卡 A100 级 |
| LoRA（bf16 主干） | 14 GB（冻结） | ~0.1 GB（仅 BA） | ~0.3 GB | 2~8 GB | **≈16~24 GB** | 单张 24GB 卡 |
| QLoRA（NF4 主干） | ≈3.5 GB（冻结） | ~0.1 GB | ~0.3 GB | 2~6 GB | **≈6~10 GB** | 12GB 级起步 |

（LoRA 参数以 r=8、挂全部线性层计，约占主干 0.5% 量级；激活随 batch 与 cutoff_len 波动，
是表中弹性最大的项。）

结论回扣阶段 4：**毕业项目 = QLoRA + 7B + 一张 24GB 卡（或对应云实例）**，账就是这么算出来的。

### QLoRA 的代价

- 训练速度比 LoRA 慢一些（前向要反量化 NF4，约慢 20%~30% 量级）——用时间换显存，值。
- 效果：论文结论是与 16bit 微调相当；实践中小幅差异存在，对教学/领域微调无碍。

## 练习

1. 白板推导：设 $d=4096$，$r=8$，LoRA 挂在一个 $d \times d$ 的线性层上，可训练参数占
   原层的百分比是多少？
   提示：$2 \times d \times r / d^2 = 2r/d$，代入算。
2. 解释给同事：为什么「B 零初始化」保证了训练起点模型行为与原模型完全一致？
   提示：前向 $Wx + BAx$，第一步 $BA=0$。
3. 用你自己的语言写 5 句话回答：为什么低秩增量足以适配新任务？
   提示：内在维度假设 + 「任务改变量集中在少数方向」+ 工程师转岗类比。
4. 查阅 QLoRA 论文摘要（arXiv 2305.14314），找出它报告的最小可行 GPU（量级即可），
   与第 4 节表格互相印证。
   提示：论文亮点之一就是单张小显存卡微调 65B。
5. 思考：你的毕业项目里，哪些输出行为希望 LoRA「打补丁」改变，哪些必须依赖底座原有能力？
   提示：格式/话术/领域术语=补丁可学；通用推理/代码能力=靠底座（呼应阶段 4 L01「能力看底座，
   行为看微调」）。

## 小结与自测

1. **Q：写出 LoRA 公式并说明各矩阵尺寸与初始化方式。**
   A：$W'=W+BA$，$W$ 冻结为 $d\times d$；$A$ 为 $r\times d$ 随机初始化；$B$ 为 $d\times r$
   零初始化；$r\ll d$。
2. **Q：LoRA 推理为什么零额外延迟？**
   A：训练后可将 $BA$ 合并进 $W$（$W+BA$），推理图与原模型完全同构。
3. **Q：内在维度假设说的是什么？**
   A：适配新任务所需的权重改变量是低秩的——只需在少数方向上调整，故小 r 的 $BA$ 够用。
4. **Q：QLoRA 相比 LoRA 改了什么、付出什么？**
   A：把冻结主干从 bf16 换成 NF4 量化（加双量化省元数据）；显存从 ~20GB 降到 ~8GB，
   代价是前向反量化让训练慢约两三成。
5. **Q：r=8、alpha=16 时，缩放系数是多少？为什么要设 alpha=2r？**
   A：缩放 $\alpha/r=2$；保持该比值稳定，调 r 时增量输出量级不变，学习率可沿用。
