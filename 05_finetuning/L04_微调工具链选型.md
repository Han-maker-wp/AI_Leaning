# 第 4 课：微调工具链选型
> 🎬 开场钩子：选框架和当年选 Spring Cloud 还是 Dubbo 是同一种纠结：生态、学习曲线、社区活跃度。今天给你一张对比表和一个明确建议——先跑通再谈优雅，工具永远服务于「把模型调出来」这个目标。


> ⏱ 建议学时：1.5~2 小时（含环境准备与自检）

## 本课目标

1. 能对比 LLaMA-Factory / Unsloth / TRL 三大方案的特点，说清各自的适用人群。
2. 能论证本课程的选型：LLaMA-Factory 起步（全流程 WebUI+CLI 生态），后期按需扩展。
3. 能搭好微调环境：uv/conda 虚拟环境、CUDA/PyTorch 匹配、安装并自检 LLaMA-Factory。
4. 建立「版本意识」：知道所有安装命令以官方 README 为准，踩版本坑时知道去哪查。

## 1. 三大方案对比

| 维度 | LLaMA-Factory | Unsloth | TRL |
|---|---|---|---|
| 形态 | 配置/YAML + CLI + WebUI 的一站式框架 | 加速库（基于 patched 的训练路径） | HuggingFace 官方 Trainer 库 |
| 上手成本 | **低**（WebUI 点选即可开训） | 低-中（notebook 教程友好） | 高（写训练代码） |
| 灵活性 | 中（配置项覆盖主流需求） | 中 | **高**（代码级控制一切） |
| 显存/速度 | 标准水平 | **省显存、速度快**（单卡/Colab 优势明显） | 标准（取决于你怎么写） |
| 生态 | 模型/模板/数据格式支持极广，README_zh 文档全 | 官方 Colab 笔记本丰富，社区活跃 | 与 transformers/PEFT 无缝，huggingface.co/learn 有官方课程 |
| 适合 | **入门首选**、快速迭代全流程 | 显存紧张的单卡/免费 Colab 场景 | 研究型定制、需要魔改训练逻辑 |
| 注意 | 抽象层多，出问题排查要看文档 | 对模型/版本组合有兼容要求 | 一切自己搭：数据、模板、导出都要手写 |

**选型建议（本课程路线）**：

- **首推 LLaMA-Factory 起步**：它把「模型 × 模板 × 数据格式 × 训练方法 × 导出部署」全链路
  标准化了，你只需专注两件事——数据质量和超参。对第一次跑通全流程的人，这是最短路径。
- Unsloth 作为「显存急救包」了解：当你只有一张小卡（或用免费 Colab）而 LLaMA-Factory
  跑不动时，换它（代价：可 tinkering 的空间变小，部分模型支持有滞后）。
- TRL 作为「进阶方向」储备：毕业项目之后若要做深度定制（自定义损失、课程学习、
  复杂偏好训练），再学它，此时你已有全流程概念，学起来快。

这与你学 Java 的路径同构：先用 Spring Boot 快速干活，需要时再下沉到 Servlet/字节码层。

## 2. 环境准备

### 2.1 为什么必须虚拟环境

微调生态的依赖（torch/transformers/peft/accelerate/deepspeed…）版本耦合紧，同一台机器上
不同项目共享一套依赖迟早打架——就像把所有 Java 项目的依赖全倒进同一个 lib 目录。
每个微调项目独立环境是铁律。

### 2.2 两种建环境方式（任选其一）

```bash
# 方式 A：conda（传统主流）
conda create -n llmft python=3.10 -y
conda activate llmft

# 方式 B：uv（新一代，速度极快；安装见 uv 官方文档）
uv venv --python 3.10 .venv
source .venv/bin/activate
```

Python 版本跟随所选工具链官方要求（一般 3.9~3.12 皆可，以官方 README 为准）。

### 2.3 CUDA / PyTorch 匹配（坑最多的环节）

核心概念：**驱动 ≥ CUDA Runtime**。`nvidia-smi` 右上角显示的是驱动支持的最高 CUDA 版本，
PyTorch 装的 runtime 版本不能超过它。匹配步骤：

```bash
# 1. 看驱动支持的最高 CUDA 版本
nvidia-smi | grep "CUDA Version"    # 例如显示 12.4

# 2. 按 pytorch.org 官网选择对应版本的安装命令（典型示例）
pip install torch --index-url https://download.pytorch.org/whl/cu124
# cu124 对应 CUDA 12.4；驱动显示 12.4 及以上即可用

# 3. 验证 GPU 可用
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
# 期望输出形如：2.x.x+cu124 True NVIDIA GeForce RTX 4090
```

云平台（AutoDL 等）直接选「预置 PyTorch 镜像」可跳过此步——这是阶段 4 L06 推荐镜像的原因。

### 2.4 安装 LLaMA-Factory（典型流程）

```bash
# 方式一：pip 安装（版本以官方 README 为准）
pip install llamafactory

# 方式二：源码安装（可锁定版本、便于查阅数据/模板源码，推荐项目期使用）
git clone https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory
pip install -e ".[torch,metrics]"
```

### 2.5 环境自检思路

```bash
# 检查 torch/CUDA 可用性
python -c "import torch; print(torch.cuda.is_available())"

# LLaMA-Factory 提供的环境自检命令（参数以官方 README 为准）
llamafactory-cli env
# 输出里确认：torch 版本、CUDA 可用、显存识别正常
```

自检要确认的四件事：① torch.cuda.is_available() 为 True；② 显卡型号与显存识别正确；
③ transformers/peft 版本能被正常 import；④ 磁盘空间足够（模型缓存 + 权重导出，按 L04 算）。

## 3. LLaMA-Factory 的心智模型（动手前建立全局图）

它把一次微调抽象为四要素，L05 实操就按这个顺序走：

```
1. 模型：model_name_or_path（HF id 或本地路径）+ template（chat template 名，阶段 4 L03）
2. 数据：data/ 目录下放数据文件 + dataset_info.json 注册（声明格式与字段映射）
3. 训练：yaml 配置（stage: sft / finetuning_type: lora / quantization_bit: 4 …）
4. 产物：adapter 权重（saves/ 目录）→ 导出合并 → chat 验证 → 部署
```

两条使用路线（L05 都会走）：

- **CLI + yaml**：可版本化、可复现——毕业项目最终交付用它。
- **WebUI**（`llamafactory-cli webui`）：浏览器里点选参数直接开训，第一次跑通全流程的最佳
  路径；确定参数后再沉淀为 yaml。

## 4. 版本意识（本课的隐性考点）

微调生态版本迭代极快，请养成三个习惯：

1. **安装命令一律以官方 README / 文档为准**（本讲义所有命令都是「典型示例」）。
2. 项目锁定版本：`pip freeze > requirements.txt`（或用 uv/conda 的 lock 机制），实验可复现
   的前提是环境可复现。
3. 报错先看三处：官方仓库 Issues（大概率有人踩过）、自己的版本组合（torch × transformers ×
   工具版本）、数据格式（下一课你会看到格式错误占了报错的一半）。

> 🍿 彩蛋｜胶水工作的价值：LLaMA-Factory 这类项目做的事，本质是把底层库的调用组装成人人能用的界面——像极了当年把 Servlet 封装成 Spring 的那批人。用框架时不卑不亢：理解底层，才配得上「会用」二字。

## 小结与自测

1. **Q：三大工具各自的定位一句话？**
   A：LLaMA-Factory=一站式低门槛全流程；Unsloth=单卡/Colab 显存与速度特化；TRL=HF 官方
   代码级控制库。
2. **Q：为什么课程首推 LLaMA-Factory？**
   A：模型/模板/数据/训练/导出全链路标准化，入门者只需专注数据与超参，是跑通第一次全流程
   的最短路径。
3. **Q：nvidia-smi 显示的 CUDA Version 含义？装错会怎样？**
   A：驱动支持的最高 CUDA 版本；PyTorch runtime 超过它则 torch.cuda.is_available() 为 False。
4. **Q：CLI+yaml 与 WebUI 各自的价值？**
   A：WebUI 快速探索参数；yaml 可版本化可复现，是项目正式交付形态。
5. **Q：微调前环境自检确认哪四件事？**
   A：CUDA 可用、显卡与显存识别正确、依赖 import 正常、磁盘空间足够。
