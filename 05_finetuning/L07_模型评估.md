# 第 7 课：模型评估
> 🎬 开场钩子：训练完的模型说「效果不错」——不错是多少？比微调前好在哪？说不清这三个问题，微调等于白做。今天这课解决「怎么证明你的模型更好了」，它直接决定毕业项目的报告有没有说服力。


> ⏱ 建议学时：2.5~3 小时（本课直接决定毕业项目报告的质量）

## 本课目标

1. 能说清「三层评估」各自要回答的问题：通用能力回归 / 领域任务效果 / 自动化评估。
2. **会自建领域评估集**：微调前封存、题目设计、人工评分表制作。
3. 能正确使用 LLM-as-judge：prompt 写法、偏差控制、与人工评分的校准。
4. 会设计「微调前后对比实验」：同 prompt 集合、同采样参数、盲评。
5. 效果不好时，能按归因路径定位问题（数据量？数据质？超参？过拟合？）。

## 1. 为什么评估这么难

LLM 评估的三大难：输出开放（没有唯一标准答案）、能力多维（一个分数说不清）、
对比条件易失控（温度不同都能「比」出错）。所以不能「问几句感觉不错」就算评估——
感觉会骗人，尤其是你自己微调的模型（禀赋效应）。

三层评估框架，每层回答一个问题：

```
第一层 通用能力回归 —— 「微调有没有把模型调傻？」
第二层 领域任务评估 —— 「在目标领域的表现提升了多少？」（微调的初心）
第三层 自动评估    —— 「能不能不靠人肉快速迭代？」
```

## 2. 第一层：通用能力回归（防「调傻」）

### 2.1 benchmark 概念

通用能力基准（MMLU、CMMLU、C-Eval 等）是标准化选择题考试：涵盖学科/常识/推理，
自动判分、可横向比较。CMMLU/C-Eval 是中文向的常用基准。

### 2.2 怎么用（概念级）

- 评估方式：用开源评测框架（如 OpenCompass 等）或 LLaMA-Factory 等工具提供的评测入口，
  对微调前后模型跑同一基准（具体命令以所用工具文档为准）。
- **不必追求分数绝对值**，看「前后变化量」：下降 1~2 个点属正常波动/对齐税（阶段 4 L01）；
  下降显著（如 5+ 个点）= 灾难性遗忘信号，回 L10 查数据配比与超参。
- 轻量替代：没有条件跑基准时，自备 20~30 道「通用题」（常识、闲聊、通用代码、写作），
  前后对比回答质量——粗糙但有效的烟雾测试。

## 3. 第二层：领域任务评估（本课核心）

### 3.1 铁律：评估集必须在微调前封存

**从你构建数据集的第一天起，先切出评估集**（建议 50~100 条），物理隔离：
不进训练 json、不参与任何清洗后的训练文件、存独立目录。原因：评估集混进训练集 =
考试泄题（数据泄漏，L10 坑课详述），你的「提升」全是背题，一上生产就现形。

评估集设计要点：

- **只从测试角度出题**：覆盖任务的类型分布，含「边界题」（该拒答的、信息不足的、超纲的）
- **难度分层**：简单/中等/困难各占一定比例，避免全是送分题
- **含对比题**：同题在微调前后的输出差异是否真的存在

### 3.2 人工评分表怎么做

开放生成任务用「维度打分」而非「总分感觉」。以 Java 代码助手为例：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 正确性 | 代码错误/答非所问 | 小瑕疵可运行 | 完全正确 |
| 完整性 | 严重缺漏 | 基本覆盖要求 | 完整覆盖全部要求 |
| 格式遵循 | 不符约定格式 | 部分符合 | 严格符合（如要求的输出结构） |
| 简洁性 | 大量废话 | 略有冗余 | 干净利落 |

要点：a) 维度对齐你的微调目标（格式遵循是微调最容易见效的，单列）；b) 每档有**可操作的
判据**（「基本覆盖」要能说清）；c) 每题都按维度打分，最后按维度汇总——总分抹平信息。

### 3.3 对比实验的正确姿势

同 prompt 集合、同采样参数（建议 temperature 低或固定 0 保证可复现）、同评估表——
只有「模型」这一个变量。有条件时做**盲评**：打乱两个模型的输出顺序（A/B 随机）再评分，
报出分数后才揭晓谁是微调版。盲评消掉的最大偏差就是「你希望它变好」。

产出物模板（毕业项目报告核心章节）：

```
评估集：N 条（类型分布、来源、封存时间）
采样参数：T=0.x，max_tokens=…
结果：维度A 前后 3.1 → 4.2；维度B …；通用回归：CMMLU 前后 x → y
结论：领域格式遵循显著提升；正确性小幅提升；未见遗忘
```

## 4. 第三层：自动评估（LLM-as-judge）

### 4.1 原理与 prompt 写法

用强模型（比你微调的模型更强的 API 或开源大模型）当「阅卷老师」，对每条输出按你的
评分表打分。judge prompt 的五个要素：

1. **角色与任务**：「你是代码质量评审员，对以下回答按维度打 1~5 分」
2. **评分细则**：把 3.2 的人工评分表原样给它（每档判据写清）
3. **评分对象**：题目 + 待评回答
4. **输出格式**：要求结构化输出（每维度的分数 + 一句理由），便于程序解析
5. **防套话**：明确「不要因为礼貌/长度加分，只按细则判」

### 4.2 偏差与校准（必须知道的三件事）

- **位置偏差**：judge 对并排比较中的先后顺序有偏好——做 A/B 对比时交换顺序各评一次
- **长度偏差**：judge 偏爱长回答——细则里明确「长度不作为加分项」
- **自偏偏差**：judge 偏爱自己风格的输出——用与被评模型不同家族的 judge 更稳

**校准动作**：随机抽 20 条，你自己人工打分并与 judge 分数对齐——一致率可接受
（例如 Pearson 相关高、排序基本一致）才允许用 judge 放量。judge 是「人工评分的放大器」，
不是替代品。

### 4.3 在迭代中的位置

数据 → 训练 → **自动评估全量** → 人工抽检校准 → 决定下一步（补数据/调参/收工）。
自动评估把你每次迭代的反馈周期从「一下午人肉评分」压到「几分钟」。

## 5. 效果不好时的归因路径

按顺序排查（每步一个动作）：

```
1. 数据量够吗？      → 每类任务 <100 条时，先补数据再谈其他
2. 数据质好吗？      → 抽 20 条训练数据人工过：答非所问/错误率高 → 回 L02 重洗
3. 学到了吗？        → 看 train loss：根本没降 → 超参问题（lr 太小/epoch 太少）
4. 学过头了吗？      → loss 很低但评估差 → 过拟合，减 epoch
5. 评估本身对吗？    → 评估集泄漏？采样参数不一致？judge 有偏差？
```

常见错位：训练 loss 很漂亮但评估不涨——多半是 4（背题）或 5（评估被污染），
而不是「再训久一点」。

> 🍿 彩蛋｜盲评的严谨：评模型像评酒——把微调前后的回答打乱顺序、匿名呈现、用同一组问题，再看评分。绕开「自己孩子怎么看都好」的偏差。这套流程和临床双盲试验是同一个思想：怀疑一切主观比较，包括自己的。

## 练习

1. 为你的毕业项目设计评估集规格：条数、类型分布、边界题比例、封存方式，写成半页文档。
   提示：边界题至少 10%——「该拒答的」与「信息不足需追问的」最能暴露模型的鲁棒性。
2. 把 3.2 的评分表改造成你领域的版本（4 个维度、3 档判据），并亲手用它盲评 5 组前后对比输出。
   提示：先自己评再交换顺序复核一次，体会位置偏差不只是 judge 的问题，人也有。
3. 写出你的 judge prompt（含五要素），对 20 条输出打分，与你的人工分数对比一致率。
   提示：不一致的条目逐条看原因——多数是细则写得不够具体。
4. 归因演练：训练 loss 从 1.8 降到 0.3，但评估集上格式遵循没变化。列出你的排查顺序与假设。
   提示：先查「评估的格式判据是否与训练数据的格式一致」（教的是 A 考的是 B）。

## 小结与自测

1. **Q：三层评估各回答什么问题？**
   A：通用回归答「调傻没有」；领域评估答「目标能力提升多少」；自动评估答「如何快速迭代」。
2. **Q：评估集为什么必须微调前封存？**
   A：防止数据泄漏——评估题混入训练集等于泄题，「提升」是背题假象。
3. **Q：对比实验要控制哪三个变量？**
   A：同 prompt 集合、同采样参数、同评分标准（且最好盲评），只留模型这一个变量。
4. **Q：LLM-as-judge 的三大偏差与对策？**
   A：位置偏差（交换顺序双评）、长度偏差（细则明示不加分）、自偏（换家族 judge）；并抽检校准。
5. **Q：loss 好 but 评估差，优先查什么？**
   A：过拟合（背题）与评估有效性（泄漏/判据错位），而不是继续加训练。
