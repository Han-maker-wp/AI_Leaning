# 第 8 课：DPO 与 RLHF 进阶（选学视野课）
> 🎬 开场钩子：让模型听懂人类偏好，官方路线（RLHF）要同时伺候多个模型，工程复杂到劝退；2023 年斯坦福团队说：可以跳过中间商。这就是 DPO——把三步走压成一步到位。看懂它的直觉，你对「对齐」的理解就到了工程水位。


> ⏱ 建议学时：1.5~2 小时（定位：建立全景认知，毕业项目通常不需要动手做对齐）

## 本课目标

1. 能复述 RLHF 三阶段全貌，并解释 PPO 阶段「四个模型同时在显存」的工程复杂度。
2. 能写出 DPO 的损失直觉：从 chosen/rejected 偏好对直接优化策略，绕过 RM 与 RL。
3. 能写出 DPO 数据格式（prompt/chosen/rejected）并说明数据从哪来。
4. 能判断「什么时候需要 DPO」，以及为什么毕业项目通常不需要。
5. 了解开源实践现状：RLHF/DPO 常作为 SFT 之后的可选第二步。

## 1. 回顾：为什么 SFT 之后还有一步

阶段 4 L01 讲过：SFT 教「怎么答」，但对「多个都合理的答案里哪个更好」无能为力——
示范数据只有「好答案」，没有「比别的答案好在哪」的相对信号。这最后一层「偏好」信号，
就是对齐阶段（RLHF/DPO）的输入。

## 2. RLHF 三阶段全景（InstructGPT 路线，arXiv 2203.02155）

```
阶段一 SFT    ：instruction → 示范回答（你已掌握，本课程主线）
阶段二 RM     ：(prompt, 回答A, 回答B) + 人类排序 → 训练奖励模型打分
阶段三 PPO    ：策略模型生成回答 → RM 打分当 reward → PPO 更新策略
```

### 2.1 奖励模型（RM）

把「人类偏好」压缩成一个标量函数 $r_\theta(x, y)$（x 为 prompt，y 为回答）。训练数据是
**排序对**：标注员对同一问题的多个回答排序，RM 的损失让分数排序与人类一致。
本质是个「学会了打分的模型」——通常用一个与策略同量级的模型初始化后微调得到。

### 2.2 PPO 为什么工程复杂：四个模型同时在显存

用 PPO 做 RLHF 时，显存里同时活着：

1. **策略模型**（被训练的 LLM）
2. **参考模型**（冻结的初始 LLM，用于 KL 惩罚，防止策略跑飞）
3. **奖励模型**（打分）
4. **价值模型**（critic，PPO 的基线，估计状态价值以降低梯度方差）

四个大模型同时在显存 + 采样/打分/更新的复杂编排——这是「RLHF 工程门槛高」的具体含义。
（对比一下你熟悉的规模感：QLoRA 微调一个 7B 都要精打细算 8GB，这里是四个模型的组合，
还需要 rollout 采样与多阶段交替更新。）

顺带一个 PPO 固有风险：**reward hacking**——策略学会讨好 RM 的漏洞拿高分而非真正变好
（「为考而学」）。这正是 KL 惩罚（不许偏离参考模型太远）存在的原因。

## 3. DPO：绕过 RM 与 RL 的直路

论文思路（Direct Preference Optimization，直觉级即可）：可以证明，最优策略与奖励函数之间
存在闭式对应，于是**跳过「显式训练 RM」和「RL 循环」**，直接用偏好对构造损失：

$$\mathcal{L}_{\text{DPO}} = -\log \sigma\left(\beta\left[\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right]\right)$$

逐项直觉（不要怕符号，每个都很直白）：

- $y_w$ = **w**inning/chosen（更好的回答），$y_l$ = **l**osing/rejected（更差的回答）
- $\pi_\theta(y|x)/\pi_{\text{ref}}(y|x)$：当前模型相对**参考模型**，生成这个回答的概率
  提升了多少（对数概率比）
- 损失在最小化时做的事：**让好回答的概率比升上去、让差回答的概率比降下去**，两者的差
  越大越好（外面套 sigmoid 变成 0~1 再取负对数）
- $\beta$：温度/步长系数，控制偏离参考模型的力度（KL 约束的化身）
- 参考模型 $\pi_{\text{ref}}$：冻结的 SFT 后模型——DPO 也要一个参考模型在显存，但对比
  PPO 的四模型阵容，显存与工程复杂度大幅下降

一句话记忆：**DPO = 把「学奖励再优化」两步并成「直接对比着学」一步**。

### 3.1 DPO 数据格式

```json
{
  "prompt": "如何优雅地关闭一个 Java 线程池？",
  "chosen": "推荐使用 shutdown() 发起平滑关闭，再配合 awaitTermination(timeout) 等待任务完成；超时后可调用 shutdownNow() 强制中断。理由：……（正确、完整的回答）",
  "rejected": "直接调用 stop() 方法就可以了。（过时且危险的回答）"
}
```

- 数据来源：人工标注二选一（贵）；或「SFT 模型的多个采样 + 强模型/人工排序」（主流）；
  开源偏好数据集筛选混入
- chosen/rejected 的**差距要清晰可判**——模糊的偏好对（两个差不多好）训练信号弱
- 格式在 LLaMA-Factory 等工具中同样是注册制（`ranking: true` 一类的声明，以官方文档为准）

### 3.2 SFT 与 DPO 的分工

| | SFT | DPO |
|---|---|---|
| 教什么 | 从无到有：示范行为 | 精修：在合理选项间选更好的 |
| 数据 | instruction + 好答案 | prompt + chosen/rejected |
| 位置 | 第一步（必需） | 第二步（可选） |

## 4. 什么时候需要 DPO（以及为什么毕业项目通常不需要）

**需要 DPO 的信号**：SFT 后模型「能力够了但品味不行」——答案都对，但总是啰嗦/太短/格式
随意/该给代码不给代码，且这种系统性偏好你**难以用 SFT 数据表达**（因为问题不是「不会答」
而是「不知道哪种答法更好」）。

**毕业项目通常不需要**，理由三条：

1. 你的 SFT 数据里 output 本身就是「按目标风格写好的示范」——格式与风格问题在数据层
   已解决（这正是 L02 强调 output 质量的原因）
2. DPO 需要高质量的偏好对数据，构建成本不低于 SFT 数据，而边际收益在「已达标的 SFT」
   之后才显现
3. 评估（L07）先行：先证明 SFT 后还有系统性偏好问题，再上 DPO——而不是反过来

**答辩加分姿势**：能说清「我评估过是否需要 DPO，判断是不需要，理由是 X」，比「我做了
DPO」更能体现工程判断力。

## 5. 开源实践现状

- 主流开源模型的发布流程普遍是「预训练 → SFT（指令+对话数据）→ 偏好对齐（DPO 或其变体）」，
  DPO 系因实现简单、显存友好，已成为开源社区偏好对齐的事实主流；PPO 系在大厂内部仍在用。
- 工具链（LLaMA-Factory 等）都内置 DPO 训练支持（stage 从 sft 换为 dpo，数据换成偏好对，
  以官方文档为准）；TRL 的 DPOTrainer 是代码级入口。
- 常见顺序：SFT → 评估 → （确有偏好问题）→ 构造偏好对 → DPO → 评估对比——与我们课程的
  L05→L07 流程衔接。

## 5.1 若真要动手 DPO：三个工程经验值

（选学，供未来参考；具体以所用工具文档为准，LLaMA-Factory 的 dpo 阶段与 TRL 的 DPOTrainer
均有默认配置）

1. **学习率比 SFT 低两个数量级**（典型 5e-7~1e-6 量级）：DPO 直接移动概率比，步子大了
   模型分布崩得比 SFT 快得多——这本身就是「偏好精修」性质的体现。
2. **beta（β）从 0.1 附近起步**：β 越大越保守（贴近参考模型），越小越激进（风格变化大但
   易伤通用能力）。
3. **训练量小**：偏好对几百到几千条、1~2 个 epoch 通常足够；DPO 过训练的症状是输出多样性
   崩塌（什么问题都一个腔调）。

> 🍿 彩蛋｜「对齐」这个词：alignment 被借来专指「让模型行为对齐人类意图」。你作为 Agent 用户其实天天在对齐：写系统提示词就是廉价的「外挂对齐」，而 DPO/RLHF 是把这种约束训进权重——外挂 vs 内化。

## 小结与自测

1. **Q：PPO 阶段显存里的四个模型分别是什么？**
   A：策略模型、参考模型（KL 约束）、奖励模型、价值模型（critic）。
2. **Q：DPO 损失的一句话直觉？**
   A：相对参考模型，抬升 chosen 的对数概率比、压低 rejected 的对数概率比，差越大损失越小。
3. **Q：DPO 数据三个字段？从哪来？**
   A：prompt/chosen/rejected；人工二选一或「模型多采样+排序」，要求偏好差距清晰。
4. **Q：什么信号说明该上 DPO？**
   A：SFT 后能力达标但存在系统性品味问题（啰嗦/格式差），且难以用 SFT 示范数据表达。
5. **Q：为什么说毕业项目通常不需要 DPO？**
   A：风格格式问题已在 SFT 数据层解决；偏好对构建成本高而边际收益小；应先评估证明需要。
