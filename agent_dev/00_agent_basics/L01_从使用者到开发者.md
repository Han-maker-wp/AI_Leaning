# 第 1 课：从使用者到开发者——掀开 Agent 的引擎盖

> 🎬 开场钩子：2023 年，Andrej Karpathy 提出一个广为流传的设想——"LLM OS"：把大模型当作 CPU，上下文窗口当作内存，工具当作外设。你用过的每一个 Agent 产品——联网搜索、代码解释器、记忆助手——拆到底都是这台"操作系统"的不同配置。今天我们把引擎盖掀开：你已经开了一年这辆车，是时候认识发动机了。

⏱ 建议学时：1.5 小时（本课动手比重高，边读边敲）

## 1.1 使用者与开发者的分水岭

先做个测试：你能回答下面三个问题吗？

- ChatGPT 联网搜索时，是模型自己"会"上网，还是有人在替它上网？
- 长对话里它"记得"你三小时前说过的话，这份记忆存在哪？
- 你让它"分析这个 Excel"，是谁在读文件、谁在写代码、谁在执行？

用了一年 Agent 产品却答不上来，很正常——**产品设计的全部目标就是让你感觉不到这些机制**。而开发者的第一步，就是把这个黑盒拆成你熟悉的工程组件。好消息：拆完你会发现，里面没有魔法，全是你在 Java 世界见过的问题——协议、调度、状态管理、IO。

## 1.2 Agent 四要素解剖

一个 Agent 程序，无论产品形态多花哨，都由四个要素构成：

```
            ┌────────────────────────────────────┐
            │              Agent 循环              │
            │  （调度器：决定下一步做什么）          │
            └───────┬───────────────┬────────────┘
                    │               │
        ┌───────────▼───┐   ┌───────▼────────┐
        │  LLM（大脑）    │   │  工具（手脚）    │
        │  理理、决策、    │   │  搜索、计算、    │
        │  生成自然语言    │   │  读写文件、API   │
        └───────────────┘   └────────────────┘
                    │               │
        ┌───────────▼───────────────▼────────┐
        │  记忆（上下文 + 外部存储）            │
        │  短期：对话历史  长期：数据库/文件     │
        └────────────────────────────────────┘
```

- **LLM**：大脑。它只会做一件事——给定一段文本，预测下一段最合理的文本。它不会上网、不会算数（精确意义上的）、更不会执行代码。一切"能力"都是下一页要讲的借力。
- **工具**：手脚。模型"调用"工具的本质是：输出一段结构化的请求（"我想调 `search_web`，参数是 xxx"），由**你的代码**去真正执行。阶段 1 我们会手写这个机制。
- **记忆**：模型本身每次请求都是失忆的（第 1 课先记住这个反直觉事实，阶段 1 L04 详攻）。所谓"记得"，是把历史对话重新发一遍，或把要点存进外部存储。
- **循环**：Agent 区别于 chatbot 的关键。chatbot 是"一问一答就结束"；Agent 是"循环运转直到任务完成"——模型可能连续调五次工具、读三个文件、再汇总回答，这个"下一步做什么"的调度就是循环。

> 🍿 彩蛋｜为什么循环这么晚才火：让 LLM 反复调用工具的思路早就有，但早期模型"决定调工具"这件事本身不可靠——直到 2023 年 6 月 OpenAI 正式推出 function calling，把"模型请求调工具"变成协议保证，Agent 循环才从炼丹变成工程。你在阶段 1 亲手写的，就是这个协议。

## 1.3 把"用过"映射到构件

拿你真实用过的功能对号入座（这张表建议抄进笔记，阶段验收要能默画）：

| 你用过的功能 | 背后的构件 |
|---|---|
| 联网搜索 | 工具（一个 `web_search` 函数）+ 循环（搜索→读结果→可能再搜） |
| 知识库问答（RAG） | 工具（检索器）+ 记忆（把检索结果注入上下文）——阶段 2 整章拆解 |
| 长对话记得你 | 记忆（历史重发 + 超长时摘要压缩） |
| 代码解释器跑 Python | 工具（沙箱化的执行器）——安全边界是阶段 1 L05 的主题 |
| 一次性长文档总结 | 无循环！单次调用 + 分块——**不叫 Agent，叫 LLM 应用** |
| AutoGPT 类"自主完成任务" | 循环 + 终止条件（任务列表清空 / 最大轮数） |

注意第五行的用意：**不是所有 LLM 应用都是 Agent**。判断标准就是有没有"循环决策"。很多生产场景一个精心设计的单次调用就够了，别为了 Agent 而 Agent——这个选型直觉贯穿本轨道。

> ☕ Java 视角：四要素映射到 Java 世界你天天写的东西——LLM 是无状态的远程服务（纯函数式的 RPC），工具是你本地的方法实现，记忆是 session 存储，循环是你 Main 里的 `while(running)` 调度器。Agent 开发 = 用协议把远程服务和你本地代码缝成一个调度循环。

## 1.4 uv 工程化：先把项目骨架立起来

主线 00 阶段你已经用过 uv（`uv venv` / `uv pip install`）。从今天起升级到**项目模式**，本轨道所有代码都长在这个项目里：

```bash
# 在 agent_dev/ 下建项目（命令以 uv 官方文档为准，版本可能更新）
cd agent_dev
uv init --name agent-dev        # 生成 pyproject.toml（≈ pom.xml）
uv add openai pydantic          # 声明依赖 + 安装 + 更新 uv.lock（≈ 加 dependency 自动装好）
uv run python 00_agent_basics/code/L02_api_demo.py   # 在项目环境中运行，免激活
```

为什么用项目模式而不是裸 venv：`pyproject.toml` 声明"意图"、`uv.lock` 锁定"精确版本"，换机器 `uv sync` 一键还原——和你离不开 Maven 锁定依赖快照是同一个理由。

**API key 的注入**。所有讲义代码遵守同一约定：

```python
import os

api_key = os.environ.get("LLM_API_KEY")        # key 永远不写进代码
base_url = os.environ.get("LLM_BASE_URL")      # 兼容端点地址，可选
```

key 进环境变量（`export LLM_API_KEY=sk-xxx`），永不进 git。这不是仪式感：模型 API key 等于**计费账户的密码**，泄漏的 key 会在几小时内被扫库机器人烧光余额——这是所有 LLM 开发者的成人礼，希望你不用亲历。

> ☕ Java 视角：环境变量注入 ≈ Spring 里用 `${LLM_API_KEY}` 占位符 + 生产环境变量覆盖，而不是把密码硬编码进 application.properties。同一个习惯，换个语言而已。

## 1.5 第一个 API 调用脚本

完整可运行版在 `code/L02_api_demo.py`（下一课逐行精讲），本课先看最短可用骨架：

```python
"""第一个 LLM API 调用脚本骨架。
依赖：openai SDK（uv add openai）；需要环境变量 LLM_API_KEY（可选 LLM_BASE_URL 指向兼容端点）。
"""
import os
import sys

from openai import OpenAI   # openai SDK 同时是"OpenAI 兼容端点"的通用客户端


def main() -> None:
    api_key = os.environ.get("LLM_API_KEY")
    if not api_key:
        sys.exit("请先设置环境变量 LLM_API_KEY（export LLM_API_KEY=...），再运行本脚本")

    # 不传 base_url 时默认连 OpenAI 官方；设了 LLM_BASE_URL 则连任意兼容端点
    client = OpenAI(api_key=api_key, base_url=os.environ.get("LLM_BASE_URL"))
    model = os.environ.get("LLM_MODEL", "gpt-4o-mini")  # 模型名用环境变量覆盖，方便换

    resp = client.chat.completions.create(   # 具体参数以 platform.openai.com/docs 为准
        model=model,
        messages=[{"role": "user", "content": "用一句话解释什么是 Agent"}],
    )
    print(resp.choices[0].message.content)


if __name__ == "__main__":
    main()
```

先读懂三件事，细节都留给 L02：① `client` 拿到的是 HTTP 客户端的封装；② `messages` 是对话的完整输入（下一课的主角）；③ 返回的 `resp` 是结构化对象，`choices[0].message.content` 才是文本本身。跑通它，你已经是半个 Agent 开发者了——剩下的一半是让模型驱动你的代码。

## 小结与自测

- 问：Agent 四要素是什么？答：LLM（推理）、工具（执行）、记忆（上下文+存储）、循环（调度），缺一样都不叫完整 Agent。
- 问：Agent 和 LLM 应用的判别标准？答：有没有"循环决策"——单次调用再复杂也只是 LLM 应用。
- 问：模型会"执行"工具吗？答：不会，它只输出调用意图，执行永远发生在你的代码里。
- 问：API key 为什么必须走环境变量？答：key 是计费凭证，进 git 等于公开钱包，泄漏会被自动化扫描盗刷。
- 问：uv 项目模式比裸 venv 多给你什么？答：pyproject.toml 声明意图 + uv.lock 锁定版本，`uv sync` 可复现环境。
