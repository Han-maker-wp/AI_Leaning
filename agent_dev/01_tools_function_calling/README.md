# 阶段 1：工具调用（5 课）

> 前置：完成阶段 0（API 调用、结构化输出、异步并发三件套已上手）。
> 本阶段回答一个问题：**function calling 到底是什么？** 答案将用代码而不是概念给出——五课之后，你亲手写出的循环，就是你用过的每一个 Agent 产品的心脏。

## 阶段目标

- 手写完整的 function calling 循环：tool schema 声明 → 模型请求 → 代码执行 → 结果回填 → 终止判断
- 掌握工具设计学：参数与描述设计、错误以文本形式返回给模型、幂等、超时、日志
- 会编排多工具（注册表、并行调用、终止条件），理解 ReAct 模式（arXiv 2210.03629）与原生协议的关系
- 会做记忆与状态：窗口管理、摘要压缩、SQLite 持久化与会话恢复
- 会给文件/执行类工具立安全边界：目录 jail、最小权限、危险操作确认

## Checkpoint：不用任何框架手写迷你 Agent loop

从 `L03_mini_agent.py` 出发，交付你自己的 `my_agent.py`：

1. **至少三个工具**：计算器、文件读、文件写（可加列表目录等），每个工具带 schema、超时与结构化错误返回（L01/L02）
2. **循环骨架**：最大轮数上限、无工具请求即终止；工具异常不炸循环（L03）
3. **记忆持久化**：会话用 SQLite（或 JSON）保存，重启后能恢复上次对话继续聊（L04）
4. **安全边界**：文件工具限制在指定工作目录内（resolve + 前缀检查），文件写需确认（L05）
5. **可切换真模型**：mock 与真实 API 通过环境变量切换（有 `LLM_API_KEY` 走真，否则 mock）

验收口径：离线 mock 下完整跑通一个两轮工具链场景（读文件 → 计算 → 写结果）；口头能讲清循环每一环的输入输出。做完说「检查我的 Agent 作业」交给导师验收。

## 阶段验收标准

- 白板默写 function calling 循环的消息流转图（含 tool_call_id 配对）
- 说得出：工具错误为什么返回文本而不是抛异常；幂等在 Agent 场景为什么更重要
- 能解释 ReAct 与原生 function calling 的关系，并说出至少三种循环终止条件
- 文件工具的安全检查能徒手写出（resolve + 前缀白名单）
- 通过上述 checkpoint 项目
