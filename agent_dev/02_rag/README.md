# 阶段 2：检索增强 RAG（5 课）

> 前置：完成阶段 0（结构化输出、异步并发）与阶段 1（工具调用——RAG 的检索器在 Agent 里就是一个工具）。
> 本阶段回答一个问题：**怎么让模型的回答有据可查？** 从分块到评估，做出一个带引用、可度量、可维护的个人知识库问答 agent。

## 阶段目标

- 会做 RAG vs 微调的选型判断，并能说清两条路线何时叠加（呼应主线阶段 5）
- 掌握分块策略（固定/递归/语义）与元数据设计，知道为什么分块是 RAG 最便宜的调优旋钮
- 理解 embedding 与相似度检索的数学与工程（numpy 暴力扫 → FAISS/Chroma 的 ANN）
- 会用混合检索（BM25+向量+RRF）、rerank、查询改写解决"查不到/查不对"
- 会建评估集并度量 hit rate/MRR/忠实度，落地引用标注与增量更新

## Checkpoint：个人知识库问答 agent

选你自己的 10-30 份本地文档（笔记/文档/规范，markdown 或纯文本即可），做一个 `kb_agent.py`：

1. **索引链路**：加载 → 递归分块（带 overlap）→ 向量化 → 入库（numpy/FAISS/Chroma 任选）→ 每块带元数据（source/标题/序号）（L02/L03）
2. **检索链路**：可选做混合检索或 rerank，至少实现向量 top-k + max_distance 过滤（L04）
3. **问答链路**：检索结果组装进 prompt（含"仅根据资料回答，资料不足要明说"的指令），回答带 [1][2] 引用标注，引用可回溯到具体 chunk 与来源文件（L05）
4. **评估**：从文档自建 ≥20 条问答对，报告 hit rate@5 与 MRR；抽样 10 条人工检查忠实度（L05）
5. **工程收尾**：索引持久化（不重复建库）、文档变更支持增量更新（chunk 哈希对比）

验收口径：换一份新文档无需改代码即可重建索引；评估指标能复跑出稳定数字；答案的每条引用都能点回原始文件。做完说「检查我的 Agent 作业」交给导师验收。

## 阶段验收标准

- 能白板画出离线索引与在线问答两条链路，标出每步的输入输出
- 说得出：为什么分块影响巨大、向量检索的盲区是什么、rerank 为什么两阶段
- 给 3 个业务场景正确判断 RAG/微调/直接 prompt 的选型并陈述理由
- 通过上述 checkpoint 项目（评估指标 + 引用可回溯是硬要求）
