# Agent 领域故事集（你的"下饭"读物）

> 按时间线排的 10 个真实小故事，每个都标了对应课程——学到那课时回头看，会有"原来如此"的爽感。
> 它的定位是学习间隙**换脑子**：比刷短视频有营养，比论文轻松。所有故事均为真实史实，可以放心当谈资。
> （主线轨道另有 AI 简史故事集，本册专注 Agent 领域。）

## 2017 · 一切的地基：Transformer

大模型时代的起点是一篇标题嚣张的论文《Attention Is All You Need》（arXiv 1706.03762）：只靠注意力机制、不要循环结构——Transformer 架构就此诞生。后来所有你叫得出名字的大模型，底座都是它。没有这层的工程师视角：Agent 领域一切繁华，都盖在这篇论文的地基上。
📍 对应课程：主线 03 阶段（Transformer）；本轨道开篇的世界观

## 2022.10 · LangChain 诞生：比 ChatGPT 还早一个月

Harrison Chase 于 2022 年 10 月开源 LangChain——那时 ChatGPT 还没发布，多数人还没听说过"提示词"这个词。它最初只解决"把多次 LLM 调用链起来"这个朴素问题（名字里的 chain 由此而来），后来长成 LLM 应用开发的事实标准全家桶。启示：框架往往诞生于先行者手工重复的痛点。
📍 对应课程：03 阶段 L01 框架地图 / L02 LangChain 核心

## 2022 · ReAct：想一想，动动手

Princeton 的 Yao 等人在 2022 年提出 ReAct（arXiv 2210.03629）：让模型交替进行 Reason（推理下一步）与 Act（调用工具/执行动作），把思维链与工具调用缝进同一个循环。今天所有"Agent 循环"——包括你手写的那一个——都是这个想法的徒子徒孙。你在 03 L03 会看到，LangGraph 教程里的那张图，形状就是 ReAct。
📍 对应课程：工具调用课（手写 function calling 循环）；03 阶段 L03

## 2023.2 · Toolformer：模型自己学会"什么时候调工具"

Meta 的 Toolformer（arXiv 2302.04761）走了一条激进路线：不靠工程师写规则决定何时调工具，而是让模型在海量文本里**自学**在哪些位置插入 API 调用最有用。它证明了"调工具的时机"本身可以是被学习的能力。你手写的循环里"何时调工具"由模型输出格式驱动——Toolformer 是这个设计的学术先声。
📍 对应课程：工具调用课；04 阶段 L02（评估"模型选对工具了吗"时想起它）

## 2023.3 · AutoGPT：史上最陡的 star 曲线，和它的退潮

2023 年 3 月开源的 AutoGPT，一度是 GitHub 历史上增长最快的项目之一：自主设定子任务、自己调工具、循环执行，"自主 Agent"的想象空间被拉满。随后热潮明显退去——大量真实需求被证明只需要"一个循环加几个工具"，而想象中的全自主场景，成本、可靠性、安全性全都兜不住。留下的教训比代码值钱：**为想象中的复杂度预支真实的抽象税，是选型第一大坑**。
📍 对应课程：03 阶段 L01 框架地图 / L06 自研 vs 框架

## 2023.4 · BabyAGI：一个周末写出的祖师爷

投资人 Yohei Nakajima 在 2023 年 4 月的一个周末写出 BabyAGI：生成任务清单 → 排优先级 → 逐个执行 → 根据结果生成新任务，一个循环而已。这个"简陋"的周末项目启发了随后一大批多 Agent 编排工具。两条启示：核心调度逻辑可以极简；**把循环写明白比堆框架名词重要**。你的毕业项目积累，已经远超一个周末。
📍 对应课程：03 阶段 L05 多 Agent 协作；04 阶段 L05 毕业项目

## 2023.4 · 生成式智能体小镇：25 个 agent 的社会实验

Stanford 研究者搭了一个模拟小镇：25 个 agent 各有身份、记忆与日程，在社区里活动、交流、传播消息（arXiv 2304.03442），论文 2023 年发布后引发轰动——agent 社区里自发涌现出信息传播与社交行为。工程侧的冷思考同样有价值：25 个 agent 互相对话，通信与记忆的 token 成本、行为不可复现的调试难度，正是"多 Agent 是分布式系统问题"的最早实证。
📍 对应课程：03 阶段 L05 多 Agent 协作（通信成本控制一节的源头）

## 2023.6 · function calling 官方化：野路子变成标准件

在 function calling 出现之前，开发者靠"在提示里贴 JSON schema + 祈祷模型输出合法 JSON"实现工具调用，解析失败是家常便饭。2023 年 6 月 OpenAI 正式推出 function calling：工具定义、调用请求、结构化返回进入 API 一等公民席位。你手写循环时用的那套 tool_calls 协议，就是这次"官方化"的产物——从野路子到标准件，一个接口设计就完成了。
📍 对应课程：工具调用课（手写循环的协议层）；03 阶段 L02（结构化输出）

## 2023 · Karpathy 的"LLM OS"设想

2023 年，Andrej Karpathy 提出一个流传极广的设想：大模型是 CPU，上下文窗口是内存，工具是外设——Agent 框架则是这之上的"操作系统"。这个类比至今仍是理解技术栈分层的最好心智模型：操作系统会沉淀、会标准化（MCP 正是往这个方向走），但没人因为换操作系统而重写自己的应用程序——你的业务工具层，永远是你自己的。
📍 对应课程：03 阶段 L06 自研 vs 框架（分层策略的理论依据）

## 2024.11 · MCP 开源：工具世界的 USB 接口

2024 年 11 月，Anthropic 发布并开源 MCP（Model Context Protocol），试图解决 N 个应用 × M 个工具的适配器地狱：工具方实现一次 server，应用方接入一次 client，中间靠开放协议对话。发布后生态快速跟进，各家宿主与工具服务陆续宣布支持。对你这样的 Java 老兵，这个剧本一点都不新——JDBC、USB、REST，标准统一后生态爆发，每次都一样。
📍 对应课程：03 阶段 L04 MCP 协议
